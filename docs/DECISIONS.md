# 결정 기록

날짜, 결정, 까닭을 적는다. "사용자 결정"은 사용자가 다른 안과 견줘 고른 것이라 묻기 전에 되돌리지 않는다.

## 정한 것

### 2026-10-31 Compose Multiplatform으로 다시 만들고 iOS도 낸다 (사용자 결정)

Play에는 업데이트, App Store에는 새로 낸다. 지금 기능을 유지하면서 에디터, 꾸미기, 위젯, 태블릿 대응, 백업 개선, 수익 모델을 더한다.

### 2026-10-31 기획 → 프로토타입 → 디자인 → 개발을 Spec Kit으로 잇는다 (사용자 결정)

오발있과 같은 Spec Kit 1.2.6 파일을 가져왔고, 오발있 `/ovalit-flow`를 본떠 `/diary-flow`를 만들었다. 오발있과 달리 기획과 디자인 사이에
눌러 보는 HTML 프로토타입 단계를 둔다(사용자가 말한 순서).

### 2026-10-31 기존 기록 이전을 가장 먼저, 가장 많이 시험한다 (사용자 요청)

규칙은 `docs/migration.md`, 헌법 원칙 I. 코드를 보고 확인한 위험:

- 사진이 `cacheDir`에 있다(자르기 라이브러리 `getUriFilePath`). OS나 "캐시 삭제"로 지워질 수 있다.
- 백업이 `note.db` 파일만 올려 WAL에 남은 최근 일기가 빠질 수 있고, 사진은 아예 올리지 않는다.
- 비밀번호가 SharedPreferences에 평문으로 있다.

### 2026-10-31 같은 저장소, 같은 applicationId, 같은 Google Cloud 프로젝트

업데이트로 이어지려면 `org.sjhstudio.diary`와 Play 앱 서명 키가 같아야 한다. 드라이브 `drive.file` 스코프는 같은 프로젝트의 OAuth
클라이언트가 만든 파일만 보여서, 프로젝트를 바꾸면 사용자의 이전 백업을 찾을 수 없다.

### 2026-10-31 1.7.x 긴급 수정 없이 리뉴얼에서 한 번에 고친다 (사용자 결정, D5)

사진을 `filesDir`로 옮기고 백업 전 WAL을 합치는 작은 업데이트를 먼저 내는 안과 견줬다. 리뉴얼 전까지 캐시에서 지워지는 사진은 되찾을 수
없다는 위험을 알고 골랐다. 새 앱 이전 코드는 캐시 경로의 사진을 찾아 `filesDir/media`로 옮긴다(`docs/migration.md`).

### 2026-10-31 Firebase(Analytics, Crashlytics, Remote Config)와 RevenueCat을 쓴다 (사용자 결정, D8·D9)

Firebase는 Spark 무료 요금제, RevenueCat은 월 추적 매출 $2,500까지 무료이고 그 위는 1%다. 헌법 IV의 Google 서비스 예외에 RevenueCat을
더한다. 일기 내용, 사진, 주소, 기분은 어느 쪽에도 보내지 않는다(헌법 II).

### 2026-10-31 광고는 업데이트 직후 모든 사용자에게 보여 준다 (사용자 결정, D3 일부)

기존 사용자는 계속 광고 없음(추천안), 1년 동안 광고 없음 선물과 견줘 골랐다. 리뷰 칭찬 1위가 "광고 없음"이라 반발 위험을 알고 골랐고,
대응(이전·새 소식 화면 광고 없음, 새 소식에서 광고와 광고 제거를 숨기지 않고 알림, Remote Config 광고 스위치)은 `docs/business.md`에 있다.
광고 자리는 헌법 III 초안대로 쓰기·읽기·백업 화면을 뺀다.

### 2026-10-31 사진 한도 무료 10장·Plus 30장, 긴 변 약 2,500px 보관, 본문은 제한된 HTML (사용자 결정, 스펙 002)

- 사진 한도: 20장·30장·제한 없음 안과 견줘 사용자가 무료 10장, Plus 30장을 제안했다. 지금 앱은 제한이 없어 헌법 III의 예외로 적었고,
  이전된 일기는 한도를 넘어도 모두 남긴다. Day One 무료는 한 편 1장, 하루콩은 사진 1장이라 무료 10장도 넉넉한 편이다.
- 화질: 백업이 사용자 드라이브(무료 15GB)를 쓰므로 원본 대신 긴 변 약 2,500px로 줄여 보관한다. 원본은 사용자 사진 앱에 남는다.
- 본문 형식: 리뷰가 요청한 글자색·형광펜을 표현하려고 Markdown 대신 허용 태그만 쓰는 HTML을 쓴다. 검색용 서식 없는 글을 따로 둔다.
  레거시 글은 이스케이프해 넣고, 보이는 글이 원문과 같은지 이전 검증에 넣는다(`docs/migration.md`).

### 2026-10-31 프로토타입은 Figma에서 만든다 (사용자 결정)

`/diary-flow` 3단계를 HTML 프로토타입(Artifact) 대신 Figma 프로토타입으로 바꿨다. 무료 플랜 페이지 셋 제한 때문에 눌러 보는 흐름은
"표지 · 흐름" 페이지에 섹션 "프로토타입 · <스펙 이름>"으로 두고, 4단계 화면 디자인은 "화면" 페이지에 둔다.

### 2026-10-31 디자인 시스템을 확정한 뒤에 화면을 그리고, 색은 기존 라벤더 계열에서 출발한다 (사용자 요청)

근거 없는 초안 값으로 그린 Figma 프로토타입을 사용자가 "패딩, 글자 크기·굵기, 컴포넌트 모양, 배치, 색 모두 별로"라고 했다. 레퍼런스
시각 규격(TDS, SEED, Apple HIG, Material 3 등)을 숫자로 조사해 디자인 시스템 시안을 먼저 고르고, 그 뒤 프로토타입을 다시 그린다.
색은 기존 앱의 라벤더·라일락과 기분 파스텔을 출발점으로 한다. `/diary-flow` 3단계 앞에 이 확인을 넣었다.

### 2026-10-31 디자인 시스템 확정: 시안 B 배치 + 시안 A 색 (사용자 결정, D6)

Figma "디자인 시스템" 페이지에서 시안 A(라벤더 바탕, 지금 앱 기분 색 그대로, 일기마다 흰 카드)와 시안 B(흰 바탕과 TDS 회색, Radix
purple, 밝기를 맞춘 기분 색, Day One식 날짜 열과 평평한 줄)를 견줬다. 사용자가 배치는 B, 색은 A를 골랐다. 지금 앱의 바탕 `#F8F8FF`,
라벤더 `#DEDEFF`(구분선), 라일락 `#CAA6FE`(꾸밈), 기분 9색이 그대로 남아 기존 사용자가 같은 앱으로 알아본다. (바탕과 구분선은 같은 날 흰색·회색으로 다시 정했다.) 버튼은 라일락의 대비가
모자라 같은 계열의 Radix violet 9로 올렸다. 다크 모드는 Radix mauve 다크로 새로 정했고, 본문 글자색·형광펜 팔레트도 같이 정했다.
토큰과 근거는 `docs/design.md`, 팔레트는 `specs/002-diary-core/contracts/rich-text-html.md`에 있다.
같은 날 사용자가 바탕을 지금 앱의 `#F8F8FF` 대신 흰색으로 바꿨다(평평한 줄 배치에서 사진과 기분 색이 더 깨끗하다). 라벤더 계열은
고른 칸과 버튼 보라에 남는다(구분선과 입력칸은 아래 최종 점검에서 회색으로 바꿨다).

### 2026-10-31 디자인 시스템 최종 점검 (사용자 요청)

프로토타입 전에 TDS(코드와 문서), SEED(rootage 토큰), Apple HIG, Material 3, Day One·Apple 저널·Daylio·하루콩·Bear·Things를 다시
조사해 디자인 시스템을 점검하고 고쳤다. 바뀐 것:

- 구조 색(구분선, 시트 손잡이, 입력칸)을 보라에서 SEED 중립 회색으로 바꿨다(사용자 지적: "이런 것도 굳이 보라 계열이어야 해?").
  다크도 SEED 다크 회색으로 맞췄다. 보라는 주요 버튼·쓰기 버튼, 고른 상태, 링크에만 쓰고 하단 탭의 고른 탭은 글자색이다.
- 자간을 모두 0으로(TDS·SEED 현행에 자간 토큰이 없다), `micro`를 11에서 12로(M3 내비 바 이름 12), 날짜 숫자용 `numeral` 22/28 Medium을 더했다.
- 근거 표기를 고쳤다(SEED t10은 26, t5는 16이었다).
- 모서리 단계에 10·14·20을 넣어 TDS 버튼·토스트와 맞췄다.
- 목록 줄: 즐겨찾기 별, 두 단계 구분선, 사진 칸 1·2·3·4장 배치를 정했다(Day One). 달 머리는 Day One식 회색 띠와 견줘 띠 없이
  글자만 두기로 했다(Apple 저널·Things처럼 평평한 흰 목록과 맞는다. 사용자가 띠를 보고 "이게 맞을까?"라고 물었다).
- 시트는 TDS처럼 떠 있는 시트로, 토스트는 한 줄 알약 모양으로 바꾸고 상태(누름·비활성·포커스)와 움직임 규칙을 넣었다(M3).
- 장소·요일 글자는 `textTertiary`(3.4:1)에서 `textSecondary`(6.6:1)로 올렸다.
- 목록 모양을 피드(기본)·카드·사진 격자에서 고르게 했다(사용자 제안, 스펙 002 FR-018).
  카드형 바탕은 회색 두 단계와 연보라 두 단계를 견줘 사용자가 지금 앱 바탕 `#F8F8FF` 그대로를 골랐다(추천은 한 단계 진한 `#F0F1FE`).
  흰 카드와의 차이가 작지만 Apple 저널도 비슷한 차이(바탕 ≈`#F7F3F3`)로 카드를 나눈다. 토큰 이름은 `canvasCard`.
- 되돌리기 알림은 5초, 누르는 동안 멈춤으로 닫았다(research O5).

### 2026-10-31 앱 아이콘을 새로 만들고 스플래시도 바꾼다 (사용자 결정)

새 디자인 시스템에 맞춰 아이콘을 새로 만든다. 지금 스플래시는 0.8초 고정 대기가 있고 Android 12 이상에서 두 번 보여서, 시스템 스플래시
하나로 바꾸고 준비가 끝날 때까지만 띄운다. 아이콘 시안은 Figma에서 고르고, 스플래시 구현은 스펙 001에서 한다(`docs/design.md`).

### 2026-10-31 앱 아이콘 A2, 스플래시는 애니메이션 없이 (사용자 결정)

아이콘은 넷째 판까지 고쳐 그렸다(일러스트처럼 과함 → 픽토그램처럼 밋밋함 → 연필로 쓴 1은 과함 → 연필 다듬기). 라벤더 파스텔 연필에 밝은
바탕(흰색 → `#EFE9FF`)인 A2로 정했다. 스플래시 애니메이션은 연필 그리기 넷, 기본 효과 다섯, 연출 셋(조립, 차오름, 기분 아홉)까지 견줘 봤지만 과하거나
밋밋해서 2026-11-01 사용자가 넣지 않기로 했다. 시스템 스플래시(흰 바탕 가운데 연필)가 준비되는 동안만 보이고 일부러 기다리게 하지 않는다. 규칙은 `docs/design.md` 앱 아이콘과 스플래시.

### 2026-10-31 커밋 규칙을 Conventional Commits로 (사용자 요청)

지금 저장소는 `refact:`, `build: 1.7.4(35)`, 영어·한국어 제목이 섞여 있다. 요즘 쓰는 Conventional Commits 1.0.0에 맞춰 type(scope)!: 제목,
본문, 꼬리말(BREAKING CHANGE, Refs)을 쓰고, 저장 형식을 바꾸는 커밋은 `!`로 표시한다. 브랜치 이름, squash merge, 릴리스 태그,
commit-msg 훅 검사까지 `CLAUDE.md` "커밋 규칙"에 있다.

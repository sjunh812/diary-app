## 추천 요금제

2026-10-31 사용자가 광고를 넣고, Plus에 광고 제거를 담고, 그 아래에 광고만 빼는 단계를 두는 방향으로 추천을 요청했다. 처음 비교한 세 안은
맨 아래 "처음 비교한 안"에 남긴다. 가격은 초안이고 근거는 위 레퍼런스 표다. "(판단)"은 출처가 아니라 근거를 보고 내린 판단이다.

### 단계

| 단계 | 가격 초안 | 들어 있는 것 | 가격 근거 |
| --- | --- | --- | --- |
| 무료 | 0원 | 1.7.4 기능 전부, 리뉴얼 개선, 사진 포함 자동 백업, 기본 위젯, 오늘의 질문. 광고(아래 자리) | - |

| Plus | 월 ₩1,900 · 연 ₩14,900(7일 체험) / 평생 ₩29,000 | 광고 제거 + 한 편 사진 30장(무료 10장) + 꾸미기 전부(종이, 테마, 추가 글꼴, 기분 세트, 출시되는 팩 모두) + 꾸민 위젯 + 고급 통계 + PDF 내보내기 + 여러 기기 동기화(R3) + 앱 아이콘 | 꼬박 클라우드 연 ₩11,000, 하루콩 연 ₩18,000~₩39,000, Journey Premium ₩29,000, Diarium Pro ₩25,000 |

- 광고 제거는 평생권만 판다. 광고를 빼는 데 매달 돈을 내게 하면 반감이 크고, 한국 일기 앱의 1회 구매가 ₩4,400대에 몰려 있다(판단).
- Plus는 구독과 평생권을 같이 판다. 구독은 반복 매출이고, 평생권은 구독을 싫어하는 사용자를 위한 것이다. 평생권은 연 구독 두 해 치 정도로 둔다(판단).
- 광고 제거를 산 사람에게는 Plus 평생권 할인 상품(예: ₩24,900)을 보여 준다. 스토어에 비소모품 업그레이드 차감이 없어 RevenueCat offering으로 별도 상품을 둔다.
- 꾸미기 팩은 Plus가 아닌 사람도 하나씩 살 수 있다. Plus는 모든 팩을 포함한다.

### 광고 자리

2026-11-01 사용자 결정. 레퍼런스 앱 광고 정책 조사(아래 근거) 뒤 "보상형 + 홈·돌아보기 네이티브 + 하루 1번 전면"으로 정했다.
헌법 III도 같은 날 고쳤다.

| 자리 | 형식 | 규칙 |
| --- | --- | --- |
| 보상형 | 사용자가 눌러서 보는 동영상 | 보상은 24시간 광고 없음(전면·네이티브 모두), 꾸미기 팩 24시간 써 보기, PDF 한 번 내보내기. 무엇을 보면 무엇을 주는지 먼저 알리고, 보지 않아도 막는 기능은 없다(AdMob 보상형 정책) |
| 홈 목록(피드·카드) | 네이티브 | 다섯째 일기 아래 1개, 그 뒤 20편마다 1개. "광고" 표시(15px 이상)와 AdChoices, 일기 줄과 다른 모양·간격으로 구별한다(AdMob 네이티브 정책) |
| 돌아보기 아래 | 네이티브 1개 | |
| 저장 뒤 하루 1번 | 전면 | 그날 처음 일기를 저장하고 상세에서 목록으로 돌아갈 때 한 번만 뜬다(날짜는 자정에 바뀐다). 저장이 다 끝난 뒤라 저장은 광고와 무관하다. 업데이트 뒤 개발자 편지를 처음 보는 날은 띄우지 않는다. Remote Config로 끌 수 있다. "앱을 1분 넘게 쓴 뒤 화면이 넘어갈 때" 조건은 꺼 둔 스위치로만 남겨, 수익이 모자라면 업데이트 없이 켠다(사용자 결정) |
| 넣지 않는 곳 | - | 쓰기, 저장 과정, 일기 상세, 잠금, 백업·복원, 이전·새 소식, 설정(행동 목적 화면이라 Google 게시자 정책에 걸릴 수 있다), 앱 열기·나가기, 배너 |
| 공통 | - | 민감 카테고리 차단, 동영상 소리 기본 끔, 결제 상태(광고 제거·Plus·24시간 보상)를 확인한 뒤에만 광고를 불러온다. 일기 내용으로 광고를 고르지 않는다(헌법 II) |

광고는 보조 수익이고 주 수익은 광고 제거와 Plus다(판단). 저장 뒤 하루 1번 전면 광고의 월 수익 어림(가정: DAU의 70%가 저장, 채움 90%,
1,000회당 $4~$8, 1달러 1,400원): DAU 2,000명이면 약 21만~42만 원, 5,000명이면 약 53만~106만 원, 10,000명이면 약 106만~212만 원이다.
1분 조건을 켜면 10~20% 정도 늘어난다(판단). 실제 DAU는 Play Console로 확인해 고친다. 저장 뒤 전면 광고는 매출이 가장 크지만 하루콩·꼬박일기 1~2점 리뷰의 가장 흔한
까닭이라 안전장치를 두고, 리뷰와 해지율을 보며 Remote Config로 빈도를 조절한다.

근거(2026-11-01 조사):

- 하루콩: 무료 체험 뒤 저장할 때마다 전면 광고를 봐야 저장된다는 리뷰가 많고, 광고를 언급한 리뷰 89건 중 17건이 1~2점이다
  ([Play](https://play.google.com/store/apps/details?id=com.bluesignum.bluediary)).
- 꼬박일기: 저장·나가기·앱 열기·백업 전 전면 광고, 광고를 언급한 리뷰 130건 중 18건이 1~2점(선정적 광고, 광고 뒤 백업 멈춤)
  ([Play](https://play.google.com/store/apps/details?id=com.casoft.gbdiary)).
- 몽글하루: "쓰기·저장 중 광고 없음"을 설명 첫 줄에 내세우고, 광고를 언급한 리뷰가 모두 칭찬이다
  ([Play](https://play.google.com/store/apps/details?id=com.mongle.diary)).
- AdMob: 전면 광고는 앱을 열고 나갈 때 금지, 사용자 행동 두 번에 한 번 이하([전면 정책](https://support.google.com/admob/answer/6201362)).
  보상형은 사용자가 고른 뒤에만([보상형 정책](https://support.google.com/admob/answer/7313578)). 네이티브는 "광고" 표시 필수
  ([네이티브 정책](https://support.google.com/admob/answer/6329638)). 행동 목적 화면에는 광고 금지([게시자 정책](https://support.google.com/admob/answer/10502938)).
- 한국 Android eCPM 근사(Appodeal 2024년 4분기, 게임 위주): 배너 약 $0.15, 전면 약 $10, 보상형 약 $14
  ([보고서](https://appodeal.com/wp-content/uploads/2025/03/Quarterly_Mobile_eCPM_Report_-_Q4_2024.pdf)). 일기 앱은 더 낮을 수 있다(판단).

### 기존 사용자

**모든 사용자에게 업데이트 직후부터 광고를 보여 준다(사용자 결정 2026-10-31).** 기존 사용자만 광고 없이 두는 안, 1년 동안 광고 없음을
선물하는 안과 견줘 골랐다. 리뷰 칭찬 1위가 "광고 없음"(15건 이상)이라 반발 위험이 가장 큰 안이므로 아래를 같이 지킨다.

- 이전 중, 이전 결과, 새 소식 화면에는 광고를 띄우지 않는다. 기록이 무사히 넘어온 것을 먼저 확인시킨다.
- 광고가 생긴 것을 숨기지 않는다. 새 소식 마지막 장의 "개발자의 편지"에서 혼자 회사 일과 병행하며 만든다는 사정, 광고와 결제를 넣는 까닭, 광고 제거 방법을 만든 사람의 말로 전한다(사용자 요청, 초안은 `docs/PRD.md`). 몰래 넣은 광고로 보이면 반발이 더 크다(판단).
- Play "새로운 기능" 란에도 광고와 광고 제거를 적는다.
- 광고는 Remote Config 스위치로 끌 수 있게 만든다. 단계적 출시 중 평점이나 리뷰가 크게 나빠지면 앱 업데이트 없이 끄거나 자리를 줄인다.
- 기존 사용자 광고 제거 출시 할인(예: 처음 2주 반값)은 선택지로 둔다.

### 광고를 넣으면 따라오는 일

- 동의: UMP(유럽 등 동의 필요 지역), iOS ATT와 `SKAdNetworkItems`. 동의하지 않으면 비맞춤 광고만 받는다.
- 신고: Play 광고 ID 선언과 데이터 보안, App Store 개인정보 라벨, 처리방침의 국외 이전 항목(`docs/release.md`).
- 광고 요청에 일기 내용, 기분, 주소를 넣지 않는다(헌법 II).
- 개발 빌드는 테스트 광고만 받는다. 개발 기기에서 실제 광고를 누르면 무효 트래픽으로 잡힌다(오발있과 같은 규칙).

## 결제 화면

2026-11-01 사용자 요청: 결제 화면은 깔끔하면서 사용자가 혹하게 잘 만든다. 유명 레퍼런스를 꼭 참고하고, 삼성 One UI 설정 화면처럼 둥근 카드 안에서
짧은 Lottie 그림이 장점을 보여 주는 방식도 함께 검토한다. 레퍼런스 조사(결제 화면 구성, 전환에 영향을 주는 근거, 스토어 규정, CMP에서 Lottie)는
진행 중이고, 결과로 이 절을 채운다. 만드는 곳은 스펙 006이다.

지키는 것(조사 전에 정한 것):

- 해요체, 압박하지 않는 말투. 닫기는 처음부터 보인다. 무료로 쓰던 기능을 잠근 것처럼 보이게 하지 않는다(헌법 III).
- 가격, 기간, 체험 뒤 결제, 해지 방법, 구매 복원, 약관·개인정보처리방침 링크를 한 화면에서 보인다(App Store 3.1.2, `docs/release.md`).
- 결제 화면은 쓰는 중에는 띄우지 않는다. 사용자가 누른 곳(광고 제거 링크, 사진 11장째, 꾸미기, 설정)에서만 연다.
- Lottie 그림은 장점마다 짧게 반복하고, 동작 줄이기를 켜면 멈춘 그림으로 바꾼다.

## 결제 구현 원칙

- Android는 Play 결제, iOS는 App Store 인앱 결제. 같은 Plus를 두 스토어에서 따로 판다(Diarium처럼 플랫폼마다 따로). 플랫폼 간 구매 공유는 계정이 필요해서 하지 않는다(헌법 II: 회원 계정 없음).
- 구매 복원 버튼, 약관·개인정보처리방침 링크를 결제 화면에 둔다(App Store 3.1.2, `docs/release.md`).
- 구현은 RevenueCat KMP SDK다(사용자 결정 2026-10-31). 월 추적 매출 $2,500까지 무료이고 그 위는 1%다. 서버 없이 두 스토어 결제와 구매 상태를 다루고, StoreKit 2(Swift 전용)를 위한 Swift 브리지를 직접 만들지 않아도 된다([요금](https://www.revenuecat.com/pricing/), [purchases-kmp 4.0.0](https://github.com/RevenueCat/purchases-kmp/releases/tag/4.0.0)).
- 직접 구현하면 Google은 구매 검증과 승인을 백엔드에서 하라고 하고 기기 로직은 변조되기 쉽다고 한다([보안](https://developer.android.com/google/play/billing/security)). Plus 같은 저가 비소모품은 기기 검증으로 감수할 수 있는 수준이지만, 3일 안에 승인하지 않으면 자동 환불된다는 점은 꼭 지킨다.
- Play 결제 라이브러리는 8 이상이어야 한다(2026-08-31부터 신규·업데이트 앱).

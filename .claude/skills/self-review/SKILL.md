# 셀프 코드 리뷰

범위가 비어 있으면 `origin/develop...HEAD`와 커밋하지 않은 변경을 본다. 바뀐 줄만 보지 않고 그 줄이 든 함수와 부르는 곳까지 읽는다.
시험 통과로 끝내지 않고 실제 흐름을 따라간다. 구조·성능 기준은 `/cmp-architecture`에 있다.

## 순서

1. 자동 검사부터 돌린다. 기계가 잡는 것은 사람이 다시 보지 않는다.

   ```bash
   ./gradlew spotlessApply
   ./gradlew spotlessCheck designTokenCheck coroutineSafetyCheck stringResourceCheck unusedImportCheck detekt :composeApp:lint allTests assembleDebug
   ```

2. 아래 A~E를 차례로 본다. 길면 `/code-review high`로 후보를 넓게 모은 뒤 이 표로 거른다.
3. 결과를 "알리는 양식" 표로 먼저 보인다. 고치기 전에 보인다.
4. 고친다. 원인 자리에서 고치고 같은 꼴을 전체에서 찾는다. 고친 것은 그 변경이 처음 들어간 커밋에 fixup으로 합친다.
5. 1~4를 새 지적이 없을 때까지 되풀이한다. 회차와 결과는 PR 본문 "손으로 본 것"에 적는다.

## A. 사용자가 겪을 일

`~/.claude/CLAUDE.md` "코드 리뷰에서 먼저 보는 것" 1~7을 그대로 쓴다: 잃지 않는가, 돈과 약속, 옛 사용자, 화면이 사실을 말하는가, 쓰다가 막히지 않는가, 느리거나 반짝이지 않는가, 고치기 쉬운가.
이 앱은 일기·사진 저장, 결제 뒤 광고 제거, 백업·복원(사진 포함), 1.7.4 이전을 먼저 본다.

## B. Android·CMP 앱이면 꼭 보는 것

| 묶음 | 보는 것 |
| --- | --- |
| 생명주기 | 화면은 `collectAsStateWithLifecycle`로 모은다. 백그라운드에서 흐름이 계속 돌지 않는다. `LaunchedEffect`·`DisposableEffect` 키가 맞고, 키가 바뀔 때 앞 작업이 정리된다 |
| 회전·프로세스 종료 | 쓰던 글과 고른 값이 회전, 다크 전환, 글자 크기 변경, 프로세스 종료 뒤에도 남는다(`rememberSaveable`, 화면 모델, 저장). `remember`만으로 사용자 입력을 들고 있지 않는다 |
| 다시 그리기 | 화면 상태는 불변 값이고 목록 항목에 키가 있다. 그리는 중에 무거운 계산, 정렬, 날짜 형식 만들기를 하지 않는다(`remember(키)`나 화면 모델로). 람다·`Modifier`를 매번 새로 만들어 넘기지 않는다 |
| 스레드 | 화면 스레드에서 디스크·DB·네트워크를 하지 않는다. 디스패처는 주입한다. 취소되면 바로 멈추고 `CancellationException`을 삼키지 않는다 |
| 새는 것 | 화면 모델·싱글턴이 `Context`, 화면, 콜백을 오래 붙잡지 않는다. 열고 닫는 자원(`Source`, 커서, 리스너)을 닫는다 |
| 뒤로·화면 전환 | 뒤로 가기, 예측 뒤로, 연타 두 번 열기, 시트 위 뒤로가 맞다. 폰과 태블릿 두 칸을 함께 본다 |
| 화면 가장자리 | edge-to-edge 안쪽 여백(상태 막대, 내비게이션 막대, 키보드, 화면 구멍)이 맞다. 키보드가 입력창을 가리지 않는다 |
| 권한·실패 | 권한 거부, 다시 묻지 않음, 오프라인, 공간 부족, 빈 상태에서 화면이 멈추지 않고 할 일을 알려 준다 |
| 접근성 | 누를 곳은 48dp(iOS 44pt) 이상, 아이콘 버튼은 설명이 있고 꾸밈 그림은 없다. 글자 크기 최대에서 잘리거나 겹치지 않는다. 대비 4.5:1 |
| 플랫폼 차이 | `expect`/`actual` 양쪽이 같은 뜻으로 동작한다. iOS에서만 다른 것(뒤로 밀기, 키보드, 안전 영역, 다크 전환)을 본다. 한쪽만 있는 기능이 없다 |
| 개인정보 | 일기 내용, 사진, 주소, 기분이 로그, 사용 통계, 오류 보고, 광고에 들어가지 않는다(헌법 II) |

## C. 이 저장소의 코드 관례

`CLAUDE.md`에 정한 것이다. 검사가 잡지 못하는 부분을 사람이 본다.

- 화면 모델은 `launchSafely`·`launchWrite`·`stateInSafely`만 쓴다. 예상되는 실패는 저장소가 결과로 돌려준다.
- 한 번만 일어날 일은 `Channel` + `receiveAsFlow`. 상태에 플래그로 두지 않는다.
- 증상만 막는 `if`, 플래그, 임시 변수를 덧대지 않는다. 상태 주인과 생명주기에서 원인을 고친다.
- 색·간격·모서리·글자는 디자인 시스템 토큰과 부품만 쓴다. 맨 Material 부품(`Button(`, `Switch(`, `AlertDialog(`)을 기능 화면에서 바로 쓰지 않는다.
- 화면 문구는 문자열 리소스에 두고 `values`·`values-ko`·`values-ja`를 함께 채운다. 날짜·시각은 플랫폼 형식을 쓴다. 한국어 문구는 `korean-humanizer`·`korean-spell-check`로 본다.
- 새 화면·부품은 같은 모듈 `preview/`에 한국어 먼저, 라이트·다크, 상태마다 프리뷰를 둔다.
- 저장 형식을 바꾸면 이전·백업·복원 시험을 같이 고치고 `!`와 `BREAKING CHANGE`를 쓴다.
- 이름은 하는 일을 말한다. 줄임말과 `data`, `info`, `manager` 같은 빈 이름을 피한다. 공개 범위는 가장 좁게(`private`, `internal`).
- 시험은 대역을 쓰고, 실제 시간을 기다리지 않고, 고친 부분을 되돌리면 실패한다.

## D. 코드 정렬과 정리

- `./gradlew spotlessApply`로 ktlint(`android_studio`, 한 줄 140자)에 맞춘다. 포맷만 바꾼 것은 기능 변경과 다른 커밋으로 둔다.
- 안 쓰는 import, 함수, 변수, 매개변수, 리소스 문자열, 파일을 지운다. `unusedImportCheck`가 import를, detekt가 일부를 잡는다.
- import는 ktlint 순서(알파벳, 별표 없음). 같은 이름이 겹칠 때만 `as`로 바꾼다.
- 주석으로 막아 둔 코드, 쓰지 않는 기본값, 한 번만 쓰는 짧은 도우미를 남기지 않는다.
- 같은 꼴이 셋 이상 되풀이되면 묶을 곳을 찾는다. 둘이면 그대로 둔다.

## E. 주석

`~/.claude/CLAUDE.md` "주석"을 따른다.

- 짧게, 한 줄에 한 가지. 명사형으로 끝낸다. 예: "액티비티 생명주기 문제가 있어 해당 화면 제거".
- 왜 그렇게 했는지만 남긴다. 코드가 이미 말하는 것, 경위, 날짜, 작업 번호는 커밋과 문서로 보낸다.
- 공개 함수와 클래스는 무엇을 하는지 한 줄 KDoc. 바뀐 코드와 어긋난 주석은 고치거나 지운다.
- 번역투와 AI 티("~를 통해", "~하는 것이 중요")를 쓰지 않는다.

## 알리는 양식

```markdown
| 등급 | 어디 | 무엇이 문제인가 | 사용자가 겪는 일 | 처리 |
| --- | --- | --- | --- | --- |
| 🔴 | `HomeViewModel.kt:42` | 저장 실패를 삼킴 | 저장된 줄 알고 앱을 닫으면 글이 사라짐 | 고침: 실패 알림, 시험 추가 |
| 🟡 | `EntryRows.kt:88` | 그릴 때마다 날짜 형식 만듦 | 긴 목록 넘길 때 버벅임 | 고침: 화면 모델로 옮김 |
| ⚪ | `PreviewText.kt:12` | 주석이 코드와 어긋남 | 없음(유지보수) | 고침 |
```

- 🔴 꼭 고침: 기록 손실, 결제·광고 약속 어김, 앱 꺼짐, 화면이 사실과 다름, 개인정보가 나감
- 🟡 고치면 좋음: 성능, 구조, 막히는 흐름, 접근성
- ⚪ 참고: 정리, 이름, 주석, 포맷
- "처리"에는 고침, 고치지 않음(까닭), 사용자에게 물음 중 하나를 쓴다. 못 본 것은 못 봤다고 적는다.

# Figma 규격 검사와 고치기

`docs/design.md`가 규격의 원본이다. 이 스킬은 값을 정하지 않는다. 재고, 어긋난 곳을 규격에 맞춘다.

## 준비

1. `figma_get_status`(필요하면 `ToolSearch`로 figma-console 도구를 불러온다)로 Desktop Bridge 연결을 본다.
   안 붙어 있으면 사용자에게 Figma 파일 "1일 1일기"에서 Desktop Bridge 플러그인을 실행해 달라고 한다.
2. `figma_execute`에는 늘 `fileKey`를 넘긴다. 같은 브리지에 다른 파일이 붙어 있을 수 있다. 파일 키는 `docs/PRD.md`와 메모리의 `figma-design-file`에 있다.

## 재기

`scripts/figma/audit.js` 내용을 그대로 `figma_execute`에 넣어 돌린다. 읽기만 한다. 잡는 것은 칩 규격, 손으로 찍은 부품, 글자 규격, 글자 스타일 없음, 안쪽 여백, 모서리, 변수 없는 색, 테마가 다른 부품이다.
화면을 고치면 이 검사를 그 턴에 돌린다. 숫자로 잡는 검사라서 눈으로 보는 점검을 대신하지 못한다.

## 고치는 순서

1. **규격이 틀렸으면 문서부터.** 값 자체를 바꿔야 하면 사용자에게 묻고 `docs/design.md`와 `docs/DECISIONS.md`를 고친다. 화면 하나를 맞추려고 따로 값을 두지 않는다.
2. **메인 컴포넌트부터.** 부품 값이 틀리면 화면의 인스턴스가 아니라 메인 컴포넌트를 고친다. 화면 단위로 고치면 같은 실수가 돌아온다.
3. **변형을 고른다.** 칩·버튼의 아이콘을 숨겨서 쓰지 않고 맞는 변형을 쓴다. 숨긴 아이콘의 여백이 남는다.
4. **손으로 찍은 것은 인스턴스로.** 칩, 버튼, 줄을 프레임으로 찍지 않는다. 시스템 부품으로 바꾸고 원래 연결을 옮긴다.
5. **색은 변수, 글자는 글자 스타일.** 부품 안 색을 원시 값으로 두지 않는다.

## 함정

- `figma_execute`가 시간 초과를 돌려도 플러그인 안에서는 코드가 끝까지 돈다. 다시 돌리기 전에 결과를 다시 읽는다. 긴 작업은 작은 호출로 나눈다.
- 한글 글자 사이에 U+2060이 끼어 있다. 글자를 찾을 때는 지우고 견준다.
- `figma.loadAllPagesAsync()`가 느리다. 한 페이지만 볼 때는 `page.loadAsync()`를 쓴다.
- 글꼴은 새 글꼴만 `{family, style}`로 읽는다. 원래 가변 글꼴을 읽으면 한 번에 수십 초 걸린다.
- `clone()`은 원래 부모에 생긴다. 임시 프레임은 `try/finally`로 지운다.

## 전체 훑기

고친 곳만 보지 않는다. 끝나면 페이지마다 확인한다.

1. 페이지 맨 위 자식 중 SECTION이 아닌 것(섹션 밖 조각)을 찾는다.
2. 겹친 사본 섹션과 섹션을 넘는 프레임을 찾는다.
3. 고친 섹션과 그 부품을 쓰는 화면을 캡처해 겹침, 잘림, 넘침을 눈으로 본다.
4. `scripts/figma/audit.js`를 다시 돌려 숫자가 줄었는지 본다.

설명 글도 사람이 읽는 디자인이다. `docs/design.md` "Figma 화면 설명"대로 짧게 쓴다.

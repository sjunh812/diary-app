# 백업·복원 왕복 시험

규칙의 원본은 `docs/backup.md` "시험"과 `specs/003-backup-v2/quickstart.md`다. 사진은 글보다 엄격하게, 모든 사진을 SHA-256으로 견준다(헌법 I).

## 먼저 지키는 것

- 에뮬레이터 Medium_Phone에 로그인된 구글 계정은 사용자 개인 계정이다. 시험 백업을 지우거나 예전 백업을 합치기 전에 묻는다.
- 구글 로그인과 비밀번호 입력은 사용자가 한다.
- 복원은 합치기가 기본이다. 바꾸기(덮어쓰기)는 사용자가 고른 시험에서만 쓴다.
- 일기 내용과 사진을 로그, 보고서, 캡처에 남기지 않는다. 견본 일기를 쓰고 숫자와 해시만 적는다.
- 설치와 지우기는 에뮬레이터에만 한다. 기기 다루는 법은 `/emulator-check`를 따른다. 빈 앱이 필요하면 `pm clear`보다 빈 에뮬레이터를 쓴다.

## 1. 자동 시험

드라이브를 흉내 낸 `FakeDrive`로 `docs/backup.md`의 묶음을 모두 돈다. 먼저 이것이 통과해야 기기로 간다.

```bash
./gradlew :shared:core:backup:testAndroidHostTest :shared:core:backup:iosSimulatorArm64Test
```

저장 형식을 바꿨으면 이전 시험과 레거시 드라이브 백업 묶음까지 함께 고쳤는지 본다.

## 2. 두 기기 왕복

A는 쓰는 기기(`emulator-5554`), B는 받는 기기(`emulator-5558`, 일기 3편이 있는 상태)다.

1. A에 일기 30편, 사진 50장을 쓴다.
2. A의 사진 해시를 적어 둔다. 사진은 `files/media` 아래에 있고, DB는 `databases/diary.db`다.

   ```bash
   adb -s emulator-5554 exec-out run-as org.sjhstudio.diary sh -c 'cd files/media && find . -type f -exec sha256sum {} +' | sort > /tmp/a-media.txt
   ```

   DB에 WAL이 남아 있을 수 있으니 파일을 꺼내 줄 수를 세기보다 앱 화면의 숫자를 함께 본다.

3. A에서 연결하고 지금 백업을 한다. 끝났다고 나오면 드라이브 웹에서 폴더, 목록 파일, 사진 수를 본다.
4. B에서 같은 계정으로 연결하고 복원 목록, 미리보기 숫자를 본 뒤 합치기를 고른다.
5. B의 사진 해시를 같은 명령으로 뽑아 견준다. A의 해시가 모두 B에 있어야 한다.
6. 양쪽 일기가 다 있는지, 기분, 날씨, 장소, 사진 순서가 같은지 본다. B에 있던 일기 3편이 그대로 있어야 한다.

## 3. 끊김과 되돌리기

1. B에서 사진을 받는 중에 비행기 모드를 켰다 끄고 앱을 다시 연다. 남은 사진만 받는지 본다.
2. 앱을 나가도 복원이 이어지는지 본다.
3. 사용자가 허락하면 B에서 바꾸기를 하고 일기 하나를 쓴 뒤 되돌린다. 바꾸기 전 일기와 새로 쓴 일기가 모두 있어야 한다.

## 4. 이전 버전 백업

1.7.4를 깔아 드라이브 백업을 한 뒤 새 앱으로 올리고, 설정 > 백업 > 이전 버전 백업을 불러온다. 같은 일기가 두 번 생기지 않는지 본다.
1.7.4 APK와 올리는 법은 `/emulator-check`의 업그레이드 시험에 있다.

## 5. iOS

Android가 만든 백업을 iOS 시뮬레이터에서 복원하고, 반대로도 한다. 구글 클라이언트 ID가 든 `iosApp/iosApp/Local.xcconfig`가 있어야 연결된다. 없으면 못 했다고 적는다.

## 보고

표로 적는다: 기기, 일기 수, 사진 수, 해시 일치 수, 중복 업로드 수, 실패와 원인. 성공 기준은 `docs/backup.md` "성공 기준"이다. 못 돌린 묶음은 못 돌렸다고 쓴다.

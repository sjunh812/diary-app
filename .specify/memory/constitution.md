# 1일 1일기 Constitution

이 헌법은 리뉴얼(Compose Multiplatform, Android 업데이트 + iOS 신규 출시)의 모든 스펙, 계획, 작업이 넘지 말아야 할 선이다.
`CLAUDE.md`의 "지켜야 할 선"과 같은 내용을 Spec Kit이 읽는 자리에 둔다.
"초안"이라 적힌 줄은 아직 사용자가 정하지 않았다. 스펙이 그 줄에 기대면 먼저 묻는다.

## Core Principles

### I. 기록은 잃지 않는다

- 1.7.4까지 쌓인 일기, 사진, 설정은 새 앱으로 하나도 빠짐없이 넘어간다. 방법은 `docs/migration.md`를 따른다.
- 이전과 복원은 원본을 고치거나 지우지 않는다. 복사하고, 줄 수와 지문으로 검증한 뒤에 바꾼다. 실패하면 새 것을 버리고 원본을 쓴다.
- 복원은 지금 기기 일기를 덮어쓰지 않고 합친다. 덮어쓰기는 사용자가 따로 고르는 선택지로만 둔다.
- 백업에는 사진이 들어간다. 백업이 끝났다고 말하기 전에 올린 파일을 다시 읽어 개수와 해시를 확인한다.
- 지운 일기는 바로 없애지 않고 휴지통에 30일 둔다(초안).
- 사진과 DB는 캐시가 아니라 지워지지 않는 앱 저장소에 둔다.

까닭: 사용자가 많고 몇 년치 기록이 있다. 지금 앱은 사진을 캐시에 두고 백업에서 사진과 최근 일기가 빠질 수 있다. 한 번 잃은 기록은 되돌릴 수 없다.

### II. 일기는 사용자 것이다

- 일기 내용, 사진, 주소는 사용자가 고른 저장소(기기, 본인 구글 드라이브, 본인 iCloud) 말고는 어디로도 나가지 않는다.
- 사용 통계, 비정상 종료 보고, 광고 요청, 문의 메일 자동 첨부에 일기 내용, 사진, 주소, 기분 기록을 넣지 않는다. 보내는 것은 화면 이름, 버튼, 개수 구간뿐이다.
- 예외 하나: 기록 이전이 일부만 된 사용자가 깨진 일기를 고쳐 받으려고 스스로 고른 경우에만, 예전 앱 일기 파일(사진과 비밀번호는 뺌)을 문의 메일에
  첨부할 수 있다. 앱은 첨부를 미리 고르지 않고, 무엇이 들어 있는지와 지우는 때를 먼저 알린다. 받은 파일은 고치는 데만 쓰고 고친 파일을 돌려준 뒤
  바로 지우며, 이 약속을 개인정보처리방침에 적는다(사용자 결정 2026-11-01). 고치는 방법이 생기면 먼저 앱 업데이트로 기기 안에서 고친다.
- 광고는 일기 내용으로 고르지 않는다.
- 잠금(비밀번호, 생체 인증)을 켠 사용자는 업데이트 뒤에도 잠긴 채로 연다. 비밀번호는 평문으로 두지 않는다.
- 회원 계정을 만들지 않는다. 구글 로그인은 드라이브 백업 권한을 받을 때만 쓴다.

까닭: 일기는 가장 사적인 기록이다. 서버가 없으니 내용이 밖으로 나갈 길을 처음부터 두지 않는다.

### III. 지금 무료인 기능은 계속 무료다

- 1.7.4에서 무료로 쓰던 기능(일기, 사진, 기분, 날씨, 위치, 달력, 검색, 통계, 다크 모드, 글꼴(본문 글꼴은 2026-11-01 사용자 결정으로 라이선스가 확인된 10종으로 바뀌었고 모두 무료), 잠금, 알림, 백업과 복원)은 리뉴얼 뒤에도 무료다. 백업에 사진이 들어가는 것도 무료다.
- 예외: 한 편에 새로 붙이는 사진은 무료 10장, Plus 30장이다(사용자 결정 2026-10-31). 지금 앱은 제한이 없었으므로 이전된 일기와 이미 붙인 사진은 한도와 상관없이 모두 남기고, 빼라고 요구하지 않는다.
- 광고는 쓰는 중과 읽는 중에는 보이지 않는다. 쓰기 화면, 저장 과정, 일기 상세, 잠금, 백업·복원, 기록 이전과 새 소식 화면에는 광고가 없다.
  저장·백업·복원은 어떤 경우에도 광고에 묶지 않는다(광고를 봐야 저장되는 일은 없다).
- 전면 광고는 하루 1번까지, 그날 일기를 저장하고 목록으로 돌아갈 때에만 띄우고 원격으로 끌 수 있어야 한다.
  앱을 열 때와 나갈 때 광고, 배너 광고는 넣지 않는다(사용자 결정 2026-11-01, 자리와 빈도는 `docs/business.md`).
- 유료는 새로 더하는 편의와 꾸미기에만 붙인다. 무엇을 묶을지는 `docs/business.md`에 둔다(초안).

까닭: 기존 사용자의 신뢰가 이 앱의 자산이다. 쓰던 기능을 잠그면 평점과 사용자를 잃는다.

### IV. 돈이 드는 서버를 두지 않는다

- 일기와 사진을 보관하는 서버를 두지 않는다. 저장 공간은 사용자 본인의 클라우드를 쓴다. 우리 비용은 0원이다.
- 꼭 필요한 작은 서버 일(공지, 새 버전 소개, 기능 스위치)은 카드 등록 없이 쓰고 한도를 넘으면 과금이 아니라 차단되는 무료 플랜에서만 돈다.
- 앱에 들어가는 라이브러리와 글꼴은 상업 이용과 앱 내장이 허락된 라이선스만 쓴다. Google 서비스(Firebase Analytics·Crashlytics·Remote Config, Play 결제, 광고를 넣으면 AdMob), Apple 서비스, RevenueCat(월 매출 $2,500까지 무료)은 예외로 둔다(사용자 결정 2026-10-31).
- 피할 수 없는 비용은 Apple Developer Program 연 99달러다.

까닭: 개인 개발자가 사용자가 늘어도 비용 걱정 없이 오래 운영할 수 있어야 한다.

### V. 심플하고, 맛있게

- 색, 글자, 간격, 모서리, 움직임은 디자인 시스템 토큰으로만 쓴다. 화면 코드에 원시 hex와 숫자 크기를 쓰지 않는다.
- 한 화면에서 강조는 한두 곳이다. 꾸밈보다 여백과 글자 크기로 위계를 만든다.
- 사용자가 고른 꾸미기(테마, 글꼴, 스티커)는 일기 안에서만 산다. 앱의 틀(탐색, 설정)은 늘 같은 디자인 시스템을 따른다.
- 디자인 시스템은 하나다. 디자인을 개발로 넘기기 전에 토스 TDS, 당근 SEED, Apple HIG, Material 3와 유명 앱에 대어 본다(흐름과 UX 패턴, 여백과 간격,
  글자 크기·굵기·줄 높이, 모서리, 누를 곳 크기, 색 대비). 고칠 것이 나오면 `docs/design.md`와 Figma를 먼저 고치고 그다음 개발한다.
  화면마다 값을 따로 맞추지 않고 토큰과 컴포넌트를 고친다(사용자 요청 2026-11-01).
- 세부 규칙은 `docs/design.md`에 있다.

까닭: 사용자가 원한 방향이다. 매일 여는 앱은 조용해야 오래 쓴다.

### VI. 어떤 기기에서도 편하다

- 폰, 폴더블, 태블릿, iPad에서 모두 쓰기 좋게 만든다. 넓은 화면은 목록과 상세를 나란히 두는 식으로 공간을 쓴다. 폰 화면을 늘리기만 하지 않는다.
- 가로·세로, 큰 글꼴, 다크 모드, 화면 읽기 프로그램에서 깨지지 않는다.
- 안드로이드와 iOS의 기능은 같다. 플랫폼에만 있는 것(위젯 구현, 결제, 클라우드)은 같은 사용자 경험을 각 플랫폼 방식으로 만든다.

까닭: 태블릿 사용자가 많고, iOS는 처음 내는 플랫폼이라 첫인상이 중요하다.

### VII. 근거를 갖고 만든다

- 기획, 디자인, 문구, 개발 모두 레퍼런스(토스, 당근, 배민, Day One, Apple, Material 등)를 실제로 찾아 출처와 함께 근거로 삼는다. 확인하지 못한 것은 못 했다고 쓴다.
- 기능은 `/diary-flow`의 순서(기획 → 프로토타입 → 디자인 → 디자인 점검 → 개발)를 따른다. 스펙 없이 화면부터 만들지 않는다.
- 남의 앱을 그대로 베끼지 않는다.

까닭: 감으로 만든 화면은 다시 고치게 된다.

## 제품 범위

- 하루를 짧고 쉽게 남기는 일기장이다. 글, 사진, 기분, 날씨, 장소가 한 편이고 달력, 목록, 통계로 돌아본다.
- 리뉴얼에서 더하는 것: 에디터, 일기 꾸미기, 위젯, 태블릿 대응, 믿을 수 있는 백업, 새 버전 소개, 수익 모델.
- 앱은 한국어, 영어, 일본어로 낸다. 맞는 언어가 없으면 영어다. 세 언어의 기능은 같고, 일기 내용은 번역하지 않는다.
- 한국어 화면 말투는 해요체다. 법적 고지만 합니다체다. 영어와 일본어 말투는 `docs/design.md` "여러 언어"를 따른다.

## 문서와 결정

- 규칙은 `CLAUDE.md`와 `docs/`(`PRD.md`, `migration.md`, `backup.md`, `design.md`, `business.md`, `release.md`)에 두고, 달라진 결정은 날짜와 까닭을 붙여 `docs/DECISIONS.md`에 남긴다.
- Spec Kit 문서(`specs/`)가 규칙 문서와 어긋나면 어느 쪽이 맞는지 정하고 같은 커밋에서 다른 쪽을 고친다.
- "사용자 결정"이라 적힌 규칙은 묻기 전에 되돌리지 않는다.

## Governance

- 이 헌법과 `CLAUDE.md`의 "지켜야 할 선"은 같은 내용이다. 하나를 바꾸면 같은 커밋에서 다른 하나도 고친다.
- 원칙을 바꾸려면 사용자가 정하고 까닭을 `docs/DECISIONS.md`에 적는다. 원칙 I은 데이터 이전이 끝나고 레거시 사본을 지우는 결정을 할 때도 다시 본다.
- 버전은 유의적 버전을 따른다. 원칙을 빼거나 뜻을 바꾸면 MAJOR, 원칙이나 절을 더하면 MINOR, 표현만 다듬으면 PATCH다.
- 모든 스펙과 계획은 Constitution Check에서 이 원칙을 하나씩 확인한다.

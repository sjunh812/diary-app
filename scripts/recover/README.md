# 깨진 일기 고쳐 돌려주기

예전 앱 일기 파일이 깨져 기록 이전이 "일부만"으로 끝난 사용자가 앱의 "첨부해서 문의"로 보낸 파일을 고쳐 돌려주는 절차다
(스펙 001 FR-010a, `specs/001-foundation-migration/contracts/migration-flow.md` "복구 문의"). 헌법 II의 예외라서
받은 파일은 고치는 데만 쓰고, 돌려준 뒤 바로 지운다.

## 받는 파일

`1일1일기-문의용-yyyyMMdd.zip`(영어 `1Day1Diary-support-…`, 일본어 `1日1日記-お問い合わせ用-…`). 안에는 `legacy-snapshot/`의
`note.db`, `note.db-wal`, `note.db-shm`, 비밀번호 줄을 뺀 `pref.xml`만 있다. 사진은 없다.

## 순서

1. 받은 zip을 저장소 밖(예: 바탕화면)에 내려받는다. 저장소, 클라우드 동기화 폴더, 메일 밖 다른 곳에 올리지 않는다.
2. 고친다.

   ```bash
   sh scripts/recover/recover-note-db.sh ~/Desktop/1일1일기-문의용-20261101.zip ~/Desktop
   ```

   받은 파일에서 읽힌 일기 수, 고친 파일의 일기 수, 넣지 못한 조각 수를 보여 준다. 받은 파일 자체는 바꾸지 않는다.
3. 고친 파일 `1일1일기-고친파일-yyyyMMdd.zip`을 같은 메일 대화에 답장으로 첨부한다. 사용자는 앱의 "파일에서 복원하기"로 고르고,
   앱은 예전 형식이라 이전 버전 백업과 같은 규칙(날짜·시각·글이 같으면 한 번만)으로 합친다(스펙 003 T086).
4. 답장을 보낸 날 지운다.
   - 내려받은 받은 파일과 만든 고친 파일(휴지통도 비운다)
   - 메일함의 첨부: 받은 메일과 보낸 답장의 첨부를 지운다. 메일 앱이 첨부만 지울 수 없으면 대화를 지운다
5. 문의 기록에 받은 날, 돌려준 날, 지운 날만 적는다. 일기 내용은 적지 않는다.

## 고쳐지지 않을 때

`.recover`로도 `Note` 표가 살아나지 않으면 그대로 알리고 받은 파일을 지운다. 사용자의 휴대폰에는 원래 기록이 그대로 있다.

# 기능 명세: 앱 테마 색

**스펙**: `010-app-theme`
**브랜치**: `feat/app-theme`
**작성**: 2026-11-22
**상태**: 확정(2026-11-22 프로토타입 사용자 확정)
**입력**: 사용자 요청(2026-11-22). "지금 앱은 브랜드 색(라벤더 보라) 하나만 쓴다. 미리 정한 몇 가지 테마 색 가운데 고르게 하고, Plus 구독자는 팔레트에서 원하는 색을 직접 찍어 테마 색으로 쓰게 한다."

## 근거

- 지금 앱은 브랜드색 토큰(`accent`, `accentText`, `selected`, `onAccent`, `surfaceCard`, `lilac`, `toneGood`, `toastAction`, `paper`, `envelopeFlap`)을 라벤더 한 벌로만 둔다(`docs/design.md` 색 표). 화면은 모두 토큰을 거치고, 온보딩·Plus 그림도 `@accent` 같은 자리표시로 토큰을 받는다. 토큰 값만 바꾸면 카드형 목록 면, 편지, 그림까지 앱 전체가 따라 바뀐다.
- 레퍼런스(공식 자료, 출처는 `research.md`)
  - 강조색만 바꾸는 앱은 5~12가지가 흔하다. Day One 글자색은 11가지이고 일부러 묶었다고 밝힌다. Todoist는 짧은 자연·음식 이름을 붙인다.
  - 직접 고르는 색은 유료 쪽이다(Daylio "custom colors", Discord 사용자 테마). Bear·Todoist는 기본 2~3가지만 무료다.
  - 다크는 고른 색에서 따로 만든다(Telegram, Linear). Day One은 밝은 저널 색이 다크에서 눈부시다고 안내한다.
  - 색 계산: 토스와 Radix 사용자 색 생성기는 OKLCH 명도로 단계를 맞춘다. Atlassian 브랜드 테마는 고른 색이 대비를 넘으면 그대로 쓴다. Radix는 밝은 색에 검은 글자를 쓴다. Apple HIG의 최소 대비는 본문 4.5:1, 굵은 글자 3:1이다.
  - 화면 모드 그림: iOS 설정 > 디스플레이 및 밝기는 라이트·다크 그림 두 장으로 모드를 고른다. 여러 개를 나란히 비교하는 작은 썸네일은 막대·상자로 줄인 그림을 쓴다(iOS, Todoist, Telegram 목록).
- 헌법 V는 "꾸미기는 일기 본문 안에서만, 고른 글꼴만 앱 전체"였다. 고른 테마 색도 브랜드색 자리에 한해 앱 전체에 쓰도록 예외를 더한다(사용자 결정 2026-11-22). 회색 구조, 기분 9색, 삭제 빨강, 본문 글자색·형광펜, 앱 아이콘과 시작 화면은 그대로다.
- 헌법 III: 테마 색은 새 기능이다. 정한 색은 모두 무료이고 직접 고르기만 Plus다(사용자 결정 2026-11-22).
- 저장 형식: 설정에 값 둘(고른 색, 직접 고른 색)이 더해지고 백업 설정 묶음에도 들어간다(사용자 결정 2026-11-22). 백업 형식 버전은 그대로다. 옛 앱은 모르는 값을 무시한다(스펙 008 서식 보기와 같은 방식).

## Clarifications

### 2026-11-22 세션

고른 시안은 Figma "프로토타입 · 시안" 페이지 "시안 · 테마 색 (고른 안 기록)"에 있다. 고르지 않은 안과 지난 판은 2026-11-22에 지웠다.

- Q: 헌법 V와 부딪치는데? → A: 브랜드색 자리만 고른 색으로 바뀌게 예외를 더한다. 디자인 시스템은 하나 그대로이고 값만 바뀐다(사용자 결정).
- Q: 무료/유료 경계는? → A: 정한 색은 모두 무료, 직접 고르기만 Plus. Plus가 끝나면 직접 고른 색을 지우고 라벤더로 되돌린다(사용자 결정 2026-11-22). 처음에는 값을 남겨 두려 했다.
- Q: 정한 색은? → A: 네 묶음(또렷한 8, 차분한 6, 파스텔 6, 넉넉한 12)을 화면에 칠해 견준 뒤, 차분한 묶음을 다크까지 고려해 넓혔다. 이름을 다시 보고 물빛→청록, 푸른 회색이라 이름과 어긋난 먹색→검정, 자두는 붉은 보라 쪽으로 옮겼고, 넉넉한 묶음의 연두를 더했다. 라벤더(기본)·자두·로즈·노을·코코아·꿀·연두·숲·청록·바다·검정 11가지까지 넓혔다가, 구독을 이끌려고 7가지로 줄였다. 정한 색이 많으면 직접 고르기를 찾을 까닭이 없다. 색 계열마다 하나만 남겨 라벤더(기본)·로즈·노을·꿀·숲·바다·검정으로 했다가, 노을·꿀이 둘 다 흐린 따뜻한 색이라 헷갈려 다시 골랐다. 자연색(로즈·귤·올리브·청록·남색)은 라벤더 옆에서 흐려 보였고, 또렷한 인기 강조색(macOS 강조색 차례: 분홍·빨강·주황·초록·파랑)은 빨강이 삭제 빨강과 겹쳤다. 울트라에서 견준 끝에 지금 앱의 라일락·기분 파스텔과 어울리는 파스텔 묶음에 검정을 더하고, 진하게 맞춘 색에 옅은 것 이름(라일락·복숭아·세이지·하늘)이 붙어 어긋나 자두·단풍·숲·바다로 이름을 고쳤다. 라벤더(기본)·자두·로즈·단풍·숲·바다·검정(사용자 결정).
- Q: 견본은 어떻게 놓나? → A: 2줄×4칸 8칸에 정한 7색과 마지막 칸 "직접 고르기"를 둔다. 직접 고르기도 같은 견본 칸이라 통일감이 있다(사용자 제안).
- Q: 직접 고르기 칸은? → A: 고른 색이 없으면 차분한 색상 고리에 가운데 +, 고른 색이 있으면 다른 견본처럼 단색 원, 쓰는 중이면 다른 견본과 같은 고름 고리·체크(사용자 결정). 세 겹 고리는 어수선해 뺐다. 무료 사용자에게만 견본 원 오른쪽 위에 작은 Plus 칩을 둔다(사용자 결정).
- Q: 화면은? → A: 설정 "화면 모드" 줄을 "테마"로 바꾸고 한 화면에 화면 모드와 테마 색을 둔다. 설정 첫 화면 줄 수는 그대로다. 맨 위 "화면 모드" 묶음에 라이트·다크 작은 홈 그림 두 장을 두고 그림 아래 동그라미로 고르고, 그 아래 "시스템 설정 따르기" 스위치 줄과 안내 문구, 그 아래 "테마 색" 8칸이다(시안 T2, 사용자 결정). 그림이 고른 테마 색으로 바뀌어 미리보기를 겸하므로 미리보기 버튼·카드·전체 화면은 두지 않는다.
- Q: 시스템 설정을 켜면 동그라미는? → A: 둘 다 비운다. "지금" 같은 표시는 뜻이 흐려 두지 않는다. 그림을 누르면 스위치가 꺼지고 그 모드가 골라진다(사용자가 판단을 맡김).
- Q: 작은 홈 그림은? → A: 우리 홈을 줄인 막대·상자 그림이고, 사용자가 고른 목록 보기(피드·카드·사진 격자)를 따른다. 사진 칸은 한 가지 회색으로 두어 테마 색(고른 칩·별·쓰기 버튼)만 강조한다. 사용자의 실제 일기는 쓰지 않는다(사용자 결정).
- Q: 직접 고르기 방식은? → A: 시트에 색 판, 색상 띠, hex 입력, [취소]·[이 색으로 하기]. 다른 시트처럼 뒤를 40% 덮고, 앱과 위 그림은 [이 색으로 하기]를 누를 때 바뀐다. 시트 안에 미리보기를 두지 않는다(사용자 결정).
- Q: 고른 색이 버튼에 어떻게 칠해지나? → A: 고른 그대로. 위 글자는 흰색과 검은색 중 APCA로 더 잘 보이는 쪽(2026-11-22 고침: 검은 글자를 쓸 수 있는데 색을 진하게 바꾸지 않는다. 같은 날 WCAG 3:1 대신 APCA로 바꿈: WCAG 2는 `#46A6FF` 같은 밝은 파랑 위 흰 글자를 실제보다 낮게 잡는다). 버튼 글자 굵기는 지금 그대로다(사용자 결정, 버튼 견본 견주기).
- Q: 설정 줄 값은? → A: "<색 이름> · <화면 모드>". 직접 고른 색은 "직접 고른 색"(사용자 결정, "내 색"은 어색해 쓰지 않음).
- Q: Plus 결제 화면은? → A: 큰 기능이라 핵심 혜택에 "테마 색 직접 고르기 / 원하는 색을 골라 테마로 쓸 수 있어요."를 더한다. 결제 화면 그림(로띠)은 네 핵심이 위쪽 120 안에서 보이게 새로 만든다(사용자 결정).
- Q: 모드를 바꿀 때 그림은? → A: 부드럽게 바뀐다(사용자 요청).
- Q: 견본 일기가 필요한가? → A: 필요 없다. 미리보기가 막대·상자 그림이라 글이 들어갈 자리가 없다(사용자 지적).
- Q: 백업에 넣나? → A: 넣는다(사용자 결정).

## 사용자 시나리오

### US1 - 정한 색 가운데 테마 색을 고른다 (P1, 무료)

누구나 설정 > 테마에서 정한 7가지 색 가운데 하나를 누르면 앱 전체의 브랜드색이 바로 바뀐다.

**왜 P1인가**: 기능의 뼈대다. 무료라 모든 사용자가 쓴다.

**독립 시험**: 무료로 설정 > 테마에서 "바다"를 누르고 홈(피드·카드·사진 격자)·달력·쓰기·돌아보기·잠금·편지·토스트·온보딩을 라이트와 다크로 본다.

1. **Given** 처음 설치 또는 업데이트, **Then** 테마 색은 라벤더이고 화면은 지금과 똑같다(토큰 값까지 같음).
2. **Given** 설정 첫 화면, **Then** "화면 모드" 줄이 "테마"로 바뀌고 값은 "라벤더 · 시스템 설정"처럼 색과 모드를 함께 보인다. 줄 수는 그대로다.
3. **Given** 테마 화면, **Then** 위에서부터 "화면 모드" 묶음(작은 홈 그림 라이트·다크, 그림 아래 동그라미와 이름), "시스템 설정 따르기" 스위치 줄과 안내 문구, "테마 색" 묶음(2줄×4칸: 정한 7색 + 직접 고르기)이 있다. 아이폰 15에서 스크롤 없이 다 보인다.
4. **When** 견본을 누름, **Then** 고른 견본에 고리와 체크가 생기고 이름이 굵어지며, 위 그림과 앱 전체가 바로 그 색으로 바뀌고 저장된다. 따로 [적용]이 없다.
5. **Given** 직접 고른 노랑처럼 밝은 색, **Then** 버튼·쓰기 버튼 위 글자와 아이콘은 검은색이다.
6. **Given** 다크, **Then** 브랜드 글자·고른 칸·편지 면은 다크용으로 계산한 값이다. 흑백은 다크에서 밝은 버튼에 검은 글자로 뒤집힌다.

### US2 - 화면 모드를 그림으로 고른다 (P1, 무료)

1. **Given** 시스템 설정 따르기 켬, **Then** 두 동그라미가 비어 있고 두 그림 모두 고름 고리가 없다.
2. **When** 다크 그림이나 그 동그라미·이름을 누름, **Then** 스위치가 꺼지고 다크가 골라지며(그림에 고름 고리, 동그라미에 체크, 이름 굵게) 앱이 다크로 바뀐다.
3. **When** 스위치를 켬, **Then** 동그라미가 비고 기기 모드를 따른다.
4. **Given** 목록 보기를 카드로 쓰는 사람, **Then** 두 그림이 카드 꼴로 보인다(피드·사진 격자도 같음).
5. **When** 색이나 모드를 바꿈, **Then** 그림이 부드럽게 바뀐다.

### US3 - Plus는 팔레트에서 직접 고른 색을 테마 색으로 쓴다 (P2, Plus)

**독립 시험**: 개발자 모드 요금제 Plus로 직접 고르기를 열어 진한 남색, 청록(`#2A9D8F`), 연분홍, 노을빛 주황, 노랑, 검정, 흰색을 차례로 고르고 라이트·다크에서 대비를 잰다.

1. **When** "직접 고르기" 칸을 누름, **Then** 시트(뒤 40% 덮음)가 열리고 위에서부터 제목, 색 판, 색상 띠, hex 입력칸, [취소]·[이 색으로 하기]가 있다. 고른 색이 있으면 그 색에서 시작한다.
2. **When** 판·띠를 끌거나 hex를 넣음, **Then** 손잡이와 hex 값이 바뀐다. 앱과 위 그림은 그대로다.
3. **When** [이 색으로 하기], **Then** 시트가 닫히고 앱과 위 그림이 그 색으로 바뀌며, 직접 고르기 칸이 고른 색 단색 원 + 고름 고리·체크가 되고 정한 견본의 고름이 풀린다.
4. **When** [취소] 또는 시트 바깥을 누름, **Then** 아무것도 바뀌지 않는다.
5. **When** 그 뒤 정한 색을 고름, **Then** 정한 색으로 바뀌고 직접 고른 색은 기억해 두어 직접 고르기 칸에 단색 원(고리 없음)으로 남는다.

### US4 - 무료 사용자는 직접 고르기에서 Plus를 안내받는다 (P2)

1. **Given** 무료, **Then** 직접 고르기 칸 원 오른쪽 위에 작은 Plus 칩이 있다.
2. **When** 누름, **Then** 시트 "테마 색 직접 고르기는 Plus에서 쓸 수 있어요" / "원하는 색을 골라 테마로 쓸 수 있어요." / [괜찮아요]·[Plus 알아보기]가 뜬다(체크리스트 Plus 시트와 같은 꼴).
3. **When** [Plus 알아보기], **Then** Plus 결제 화면으로 간다.
4. **Given** 요금제를 아직 모름(재설치 직후), **Then** Plus 칩과 안내 시트를 보이지 않고 칸을 누를 수 없게 둔다(스펙 008과 같음).

### US5 - Plus 결제·관리 화면이 새 핵심 혜택을 보인다 (P2)

1. **Given** 결제 화면, **Then** 핵심 혜택이 광고 없이 쓰기 · 한 편에 사진 30장 · 고급 통계 · 테마 색 직접 고르기 넷이고(그림의 아이콘 차례), 아이폰 15에서 스크롤이 생기지 않는다(그림 120 이상).
2. **Given** 결제 화면 그림, **Then** 아래 혜택 아이콘이 하나씩 켜지며 가운데에 그 혜택 그림(광고 띠가 ✕로 닫힘, 사진과 '30', 기분 막대, 견본을 고르면 제목 줄 색이 바뀜)이 나오고, 넷이 다 켜지면 Plus 배지로 끝나는 장면이 보인다.
3. **Given** Plus 관리 화면과 [모두 보기] 시트, **Then** 같은 넷이 같은 순서로 보인다.

### US6 - Plus가 끝나면 직접 고른 색을 지운다 (P3)

1. **Given** 직접 고른 색을 쓰던 Plus가 끝남, **Then** 직접 고른 색을 지우고 라벤더로 되돌린다. 직접 고르기 칸은 빈 칸에 Plus 칩이다.
2. **When** 다시 Plus, **Then** 라벤더 그대로이고 직접 고르기에서 새로 고른다.
3. **Given** 정한 색을 쓰던 사람의 Plus가 끝남, **Then** 고른 정한 색은 그대로이고 기억해 둔 직접 고른 색만 지운다.
4. **Given** 무료, **When** 직접 고른 색이 든 백업을 복원, **Then** 직접 고른 색은 남지 않고 라벤더다.
5. **Given** 재설치 직후처럼 요금제를 아직 모름, **Then** 아무것도 지우지 않는다.

### US7 - 백업·복원과 기기 바꾸기에서 테마 색이 따라온다 (P3)

1. **Given** 테마 색을 바꾼 기기의 백업, **When** 다른 기기에서 복원, **Then** 글꼴·화면 모드처럼 테마 색과 직접 고른 색도 돌아온다.
2. **Given** 옛 앱(테마 색 없음)이 만든 백업, **When** 복원, **Then** 테마 색은 바뀌지 않는다.
3. **Given** 이 버전의 백업, **When** 옛 앱이 복원, **Then** 모르는 값을 무시하고 나머지는 그대로 복원된다.

### Edge Cases

- 저장된 정한 색 이름을 모름(앞으로 뺀 색, 깨진 값): 라벤더로 보인다. 저장값은 사용자가 다시 고를 때까지 지우지 않는다.
- 직접 고른 색 값이 깨짐: 라벤더로 보이고 직접 고르기 칸은 비어 있음으로 보인다.
- 시작할 때: 설정을 읽기 전에는 지금처럼 바탕만 그려 다른 색이 스치지 않는다. 요금제는 기기에 남긴 값을 쓰므로 Plus의 직접 고른 색도 바로 보인다.
- 빨강 계열을 직접 고름: 삭제 버튼은 늘 `danger`와 글자로 구별된다. 고른 색을 막지 않는다.
- 글자 크기 최대, 작은 휴대폰(SE 667, 안드로이드 640dp): 화면 모드 묶음은 늘 첫 화면에 보이고, 테마 색은 스크롤해 본다. 견본 이름이 길면 두 줄까지 감싼다.
- 태블릿 두 칸, 폴드 펼침: 테마 화면은 설정 오른쪽 칸에 열리고 최대 폭 안에서 같은 배치다. 직접 고르기 시트는 다른 시트처럼 폭을 줄여 가운데 둔다.
- 다크에서 직접 고른 아주 진한 색: 다크 바탕과 3:1이 안 되면 다크에서만 밝힌다. 그 위 글자는 FR-005 규칙을 다크 값에 다시 적용한다.
- 접근성: 견본은 색 이름·고름 상태·Plus 여부를 읽어 준다. 그림·동그라미는 라디오 버튼으로 읽힌다. 판과 띠는 TalkBack·VoiceOver에서 값 조절이 되고, hex 입력칸이 정확히 고르는 길이다.

## 요구사항

### 기능 요구사항

- **FR-001**: 테마 색은 정한 7가지(라벤더·자두·로즈·단풍·숲·바다·흑백)와 직접 고른 색 하나다. 기본은 라벤더다. 정한 색 값은 `research.md` "정한 7색" 표다.
- **FR-002**: 라벤더는 지금 토큰 값을 그대로 쓴다.
- **FR-003**: 테마 색은 브랜드색 자리 토큰만 바꾼다: `accent`, `accentIcon`, `onAccent`, `accentText`, `selected`, `surfaceCard`(라이트), `lilac`, `toneGood`, `toastAction`, `paper`(다크), `envelopeFlap`. 회색 구조, 기분 9색, `danger`, 본문 `ink`·`mark`, `toneHard`, 앱 아이콘·시작 화면은 그대로다.
- **FR-004**: 토큰은 고른 색 하나에서 라이트·다크를 따로 계산한다(OKLCH, 규칙은 FR-005~FR-009, 숫자는 `research.md` "계산 규칙").
- **FR-005**: `accent`(라이트)는 고른 색을 그대로 쓴다. 위 글자는 흰색과 검은색(`#1A1C20`) 중 APCA 밝기 대비(|Lc|)가 큰 쪽이다. 흰 바탕과 1.3:1 미만인 거의 흰 색은 버튼 면이 보이도록 1.3:1까지 진하게 한다. 버튼 글자 굵기는 지금 그대로다.
- **FR-006**: `selected`는 명도 0.932, 채도는 고른 색의 21%(최대 0.045)다. `accentText`는 `selected` 위 5.0:1, 흰 바탕 위 4.5:1을 넘는 가장 밝은 값이다. 노랑은 호박 쪽, 연두는 초록 쪽으로 색상을 옮겨 글자가 올리브가 되지 않게 한다.
- **FR-007**: 다크 `accent`는 라이트 값이 다크 바탕과 3:1 이상이면 그대로, 아니면 3:1이 될 때까지 밝힌다.
- **FR-008**: 다크 `accentText`는 다크 바탕 위 8.6:1(라벤더와 같은 대비)이 되는 가장 어두운 값이다. 다크 `selected`·`paper`·`envelopeFlap`은 라벤더의 명도에 고른 색의 색상과 줄인 채도를 쓴다.
- **FR-009**: 색이 거의 없는 색(OKLCH 채도 0.03 미만)은 SEED 회색과 같은 차가운 색조로 만든다. 어두우면(명도 0.5 미만) 정한 색 흑백과 같은 값이다. 회색 테마의 `selected`는 `sunken`과 구별되게 명도 0.90(다크 0.36)이다. 채도는 0.19를 넘지 않게 줄이고, sRGB 밖이면 색상·명도는 두고 채도만 줄인다.
- **FR-010**: 계산한 토큰은 본문 글자 4.5:1, 브랜드 글자는 바탕 위 4.5:1을 모든 색에서 넘는다. 직접 고른 색의 버튼 위 글자는 APCA Lc 45(굵은 큰 글자 최소) 이상이다. 정한 7색 버튼 글자는 WCAG 4.5:1도 넘는다. 시험으로 색상환 전체와 경계 색을 확인한다.
- **FR-011**: 설정 첫 화면의 "화면 모드" 줄은 "테마"가 되고 값은 "<색 이름> · <화면 모드>"다. 직접 고른 색은 "직접 고른 색"이다.
- **FR-012**: 테마 화면은 위에서부터 "화면 모드" 묶음(그림 두 장 + 동그라미), "시스템 설정 따르기" 스위치 줄, 안내 문구, "테마 색" 묶음(8칸) 순서다. 규격은 `docs/design.md` "테마 화면"(그림 96×192·모서리 16·사이 56, 고른 그림 고리 3 띄우고 2, 그림 아래 12에 [동그라미 24 · 8 · 이름 15/22], 그 아래 24에 스위치 줄, 견본 칸 70×76·원 44·고름 고리 54, 4칸).
- **FR-013**: 견본·그림을 누르면 바로 저장되고 앱 전체가 바뀐다. 고름은 고리·체크·굵은 이름으로 알린다(색만으로 알리지 않음).
- **FR-014**: 작은 홈 그림은 사용자의 목록 보기(피드·카드·사진 격자)를 따르고, 사진 칸은 한 가지 회색이며, 고른 테마 색의 고른 칩·별·쓰기 버튼만 색이 있다. 색·모드가 바뀌면 부드럽게 바뀐다.
- **FR-015**: Plus의 "직접 고르기"는 시트(색 판·색상 띠·hex 입력·[취소]·[이 색으로 하기], 뒤 40% 덮음)다. [이 색으로 하기]에서만 저장하고 앱이 바뀐다. hex 칸은 사용자가 고른 값을 그대로 보인다.
- **FR-016**: 무료 사용자의 직접 고르기 칸에는 Plus 칩이 있고, 누르면 Plus 안내 시트, [Plus 알아보기]는 결제 화면으로 간다. Plus 사용자에게는 칩이 없다.
- **FR-017**: 결제 화면·관리 화면·[모두 보기] 시트의 핵심 혜택에 "테마 색 직접 고르기"를 넷째(그림의 아이콘 차례와 같게 맨 끝)로 더하고, 결제 화면 그림(로띠 `plus_benefits.json`)을 새로 만든다(스펙 008 FR-022).
- **FR-018**: 요금제가 Plus가 아니라고 확정되면 직접 고른 색을 지우고, 쓰던 중이었으면 라벤더로 되돌린다. 요금제를 모르는 동안에는 지우지 않는다. Plus인 동안 정한 색을 고르면 고른 값만 바뀌고 직접 고른 색은 따로 기억한다.
- **FR-019**: 설정에 고른 테마 색(정한 색 이름 또는 "직접")과 직접 고른 색(#RRGGBB)을 더하고 백업 설정 묶음에 넣는다. 백업 형식 버전은 그대로다. 복원 규칙은 글꼴·화면 모드와 같다.
- **FR-020**: Android와 iOS는 같은 공통 코드로 같은 화면과 같은 값을 그린다. 바탕화면 색 따르기(Android 12+ dynamic color)는 iOS에 없어 넣지 않는다(헌법 VI).
- **FR-021**: 새 화면 문구와 색 이름은 한국어·영어·일본어 문자열 리소스로 둔다.
- **FR-022**: 색을 바꿔도 시작 시간과 화면 전환에 깜빡임이 없다. 정한 색은 고정 값이고, 직접 고른 색만 고를 때 한 번 계산해 기억한다.

### 주요 데이터

- **테마 설정**: 고른 테마 색(`lavender` 등 정한 색 이름 또는 `custom`), 직접 고른 색(`#RRGGBB`, 없을 수 있음).
- **테마 색 토큰 한 벌**: 라이트·다크 각각 FR-003의 토큰.

## 성공 기준

- **SC-001**: 업데이트한 기존 사용자의 화면이 지금과 같다(라벤더 토큰 값 시험 100%).
- **SC-002**: 정한 7색과 색상 0°~360°를 15° 간격으로 돈 직접 색, 경계 색(검정, 흰색, 회색, 순 노랑, 연두, 연분홍, 진한 남색, 노을빛 주황)에서 FR-010 대비가 모두 넘는다(시험 100%).
- **SC-003**: 테마 색을 바꾸고 다시 시작해도 첫 화면에 다른 색이 스치지 않는다(Android·iOS 녹화로 확인).
- **SC-004**: 백업 → 복원 왕복에서 테마 색과 직접 고른 색이 돌아오고, 옛 백업·옛 앱 복원이 깨지지 않는다(`/backup-roundtrip`).
- **SC-005**: 무료 사용자가 직접 고른 색을 앱에 쓰게 되는 길이 없다.
- **SC-006**: 아이폰 15(390×844)와 안드로이드 411×914, 기본 글자 크기에서 테마 화면과 Plus 결제 화면에 스크롤이 생기지 않는다.

## 가정

- 정한 색 값은 계산 규칙으로 만든 뒤 시안에서 눈으로 다듬은 고정 값이다. 규칙을 바꿔도 정한 색은 말없이 바뀌지 않는다.
- 대비 높이기(Android `getContrast`, iOS 대비 높이기)에 맞춰 목표 대비를 올리는 것은 이번 범위가 아니다(`research.md` 열린 결정).
- 앱 아이콘 바꾸기는 Plus의 다른 기능(`docs/business.md`)이라 이번 범위가 아니다.

# Quickstart: 백업 v2 확인하기

백업 v2가 끝까지 되는지 확인하는 순서다. 명령의 정확한 모양은 스펙 001이 프로젝트 뼈대를 만들 때 `CLAUDE.md` "빌드와 시험"에 채운다.
설치는 에뮬레이터·시뮬레이터에만 한다(`ANDROID_SERIAL` 지정).

## 준비

- 스펙 001 뼈대(빌드, `diary.db` 버전 1, `media/`, 이전 견본 자료)와 스펙 002의 일기 저장이 있어야 한다.
- 구글 클라우드 콘솔에서 지금 앱과 같은 프로젝트에 Android 클라이언트(디버그 서명용 하나 더)와 iOS 클라이언트가 있어야 한다. 키와 클라이언트 ID는
  저장소에 올리지 않고 로컬 설정(`local.properties`, Xcode 설정 파일)에 둔다.
- 실제 드라이브 시험에는 시험용 구글 계정 두 개를 쓴다(하나는 공간을 거의 채워 둔다). 개인 계정은 쓰지 않는다.

## 1. 첫 작업: Android가 만든 파일을 iOS가 보는지 (research R1)

1. 시험 계정으로 Android 시험 앱(같은 프로젝트의 Android 클라이언트, `drive.file`)을 연결하고 `1일 1일기 백업/` 폴더와 파일 하나를 만든다.
2. 같은 계정으로 iOS 시험 앱(같은 프로젝트의 iOS 클라이언트, `drive.file`)을 연결하고 `appProperties`로 그 폴더와 파일을 찾는다.
3. 반대로 iOS가 만든 파일을 Android가 찾는다.
4. 1.7.4 앱(실제 Play 서명 빌드 또는 같은 클라이언트의 디버그 빌드)이 올린 `note.db`를 새 Android·iOS 시험 앱이 찾는다.

기대: 넷 다 보인다. 하나라도 안 보이면 결과를 `research.md` R1에 적고, 대안(R1의 "안 보일 때")을 사용자와 정한 뒤 다음 작업으로 간다.

## 2. 자동 시험 (드라이브 흉내)

`shared/core/backup`의 공통 시험이 `docs/backup.md` "시험" 13묶음을 모두 돈다. 드라이브는 `core/testing`의 `FakeDrive`(메모리, 확인값 계산, 공간 한도,
끊김·깨짐·토큰 만료·속도 제한 주입)로 흉내 낸다.

| 묶음 | 확인하는 것 |
| --- | --- |
| 왕복 | 백업 → 빈 기기 복원 뒤 일기 모든 칸, 사진 확인값, 사진 순서가 같다 |
| 이전 → 백업 → 복원 | 스펙 001 견본 자료(찾을 수 없는 사진 포함)가 그대로 돌아온다 |
| 레거시 드라이브 백업 | `merge-rules.md` 이전 버전 표 세 경우 |
| 끊김 | 사진 올리는 중·받는 중 끊고 다시 하면 남은 것만, 이미 올린 사진 재전송 0 |
| 반쯤 된 백업 | 목록 파일 전에 끊기면 목록에 안 보이고, 이전 백업은 그대로 |
| 큰 양 | 1만 편·1만 장(가짜 바이트), 메모리 상한 안에서 끝까지 |
| 공간 부족 | 글 먼저, 최근 사진부터, `inBackup=false` 수가 맞음 |
| 중복 | 같은 사진은 드라이브에 하나 |
| 손상 | 깨진 사진 하나만 `missing`, 깨진 목록 파일은 고를 수 없음 |
| 계정 | 만료 → 다시 연결 안내, 다른 계정과 안 섞임, 지운 폴더는 새로 |
| 동시에 | 백업·복원 중 쓴 일기가 남음 |
| 시간 | 시간대 바뀐 기기에서 날짜 그대로 |
| 자동 백업 | 미뤄진 작업이 이어지고 보이는 시각이 실제 성공 시각 |

합치기 표(`merge-rules.md`의 경우 1~7, 휴지통, 사진 줄, 바꾸기·되돌리기)는 표 하나당 시험 하나로 둔다.

## 3. 실제 드라이브 시험 (밤마다)

CI 비밀값에 시험 계정의 갱신 토큰을 두고, 왕복·끊김·공간 부족 묶음을 실제 드라이브로 돈다. 끝나면 시험 폴더를 지운다.

## 4. 기기에서 손으로

1. 에뮬레이터 A(Android)에서 일기 30편·사진 50장을 쓰고 연결 → 지금 백업. 드라이브 웹에서 폴더, 목록 파일, 사진 수를 본다.
2. 에뮬레이터 B(Android, 일기 3편 있음)와 iOS 시뮬레이터에서 같은 계정으로 연결 → 복원 목록 → 미리보기 숫자 확인 → 합치기. 양쪽 일기가 다 있는지 본다.
3. B에서 사진을 받는 중에 비행기 모드를 켰다 끄고 앱을 다시 연다. 남은 사진만 받는지 본다.
4. B에서 바꾸기 → 일기 하나 쓰기 → 되돌리기. 바꾸기 전 일기와 새로 쓴 일기가 모두 있는지 본다.
5. 공간을 채운 시험 계정으로 A를 연결해 지금 백업. 모자란 양과 못 올린 장수가 맞는지 본다.
6. 1.7.4를 설치해 드라이브 백업을 한 뒤 새 앱으로 업데이트하고, 설정 > 백업 > 이전 버전 백업을 불러온다. 같은 일기가 두 번 생기지 않는지 본다.
7. 연결하지 않은 새 설치에서 일기 3편을 쓰고 홈의 권하기 카드, "나중에" 세 번 뒤 사라짐을 본다.
8. 자동 백업: `adb shell cmd jobscheduler run`(Android), Xcode의 BGTask 시뮬레이션(iOS)으로 미뤄진 작업을 돌려 본다.

## 5. 사용 통계 점검

시험 빌드에서 Firebase DebugView로 `backup_*`, `restore_run` 이벤트를 보고, 값이 `backup-flow.md` 고정 표 밖이 아닌지 본다(SC-010).

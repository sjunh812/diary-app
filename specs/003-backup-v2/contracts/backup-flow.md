# 백업·복원 흐름, 상태 표시, 권하기, 사용 통계

화면 흐름의 확정은 3단계 프로토타입(`prototype.md`)에서 한다. 여기서는 화면 키, 언제 무엇이 도는지, 상태 표시와 알림의 규칙, 보내도 되는 값을 정한다.
형식은 [backup-format.md](backup-format.md), 합치기는 [merge-rules.md](merge-rules.md), 플랫폼 근거는 [research.md](../research.md) R14~R17이다.

## 화면 키 (Navigation 3)

| 키 | 모듈 | 내용 |
| --- | --- | --- |
| `BackupSettingsKey` | backup | 설정 > 백업. 상태, 지금 백업, 자동 백업, "백업에서 복원하기", "백업 설정", 되돌리기(7일 안). 연결 안 했으면 연결하기(예전 드라이브 백업은 연결한 뒤 복원을 권함), 파일로 백업하기 |
| `BackupOptionsKey` | backup | 백업 설정. 구글 계정, 사진은 Wi-Fi에서만, 파일로 백업하기, 연결 끊기 |
| `RestoreListKey` | backup | 드라이브 백업 목록(기기별), "이전 버전 백업" 칸, 묶음 파일 불러오기 |
| `RestorePreviewKey(source, ref)` | backup | 미리보기 숫자, 합치기(기본)·바꾸기(다른 선택지), 확인 |
| `RestoreProgressKey(jobId)` | backup | 받기, 확인, 합치기, 사진 n/N. 앱을 닫아도 다음 실행에서 이어 감 |
| `RestoreResultKey(jobId)` | backup | 결과 숫자, 찾을 수 없는 사진, 잠금 다시 정하기 안내 |
| `ExportKey` | backup | 파일로 백업하기. [파일 만들기](크기, 저장 위치 고르기), "파일에서 복원하기"(파일 고르기 → 복원 미리보기), 새 휴대폰으로 옮기는 방법. 파일 기능의 입구는 이 화면 하나다 |

- 백업과 복원은 다른 화면, 다른 색, 다른 말이다(FR-027). 설정 > 백업에서 복원은 목록 줄 하나("백업에서 복원하기")로만 들어가고, 지금 백업 버튼과
  나란히 두지 않는다.
- 백업 화면에는 자주 보는 것(상태, 지금 백업, 자동 백업)만 두고 가끔 바꾸는 것은 "백업 설정"에 모은다(사용자 결정 2026-11-01, 화면이 복잡해 보인다는 의견).
- 홈의 백업 상태 줄과 권하기 카드는 스펙 002 홈이 `BackupStatusRepository`의 흐름을 받아 그린다. 카드 컴포넌트는 `feature/backup`이 내보낸다.

## 백업이 도는 때

| 시작 | 조건 | 무엇을 |
| --- | --- | --- |
| 지금 백업 | 사용자가 누름, 연결됨 | 전부. 사진은 Wi-Fi 규칙을 따르되, 모바일 데이터면 "사진 n장은 Wi-Fi에서 올려요"와 [모바일 데이터로 올리기](이번만 허용)를 보인다 |
| 연결 직후 | 처음 연결 | 지금 백업과 같다. 자동 백업을 켠다(FR-013) |
| 자동 | 하루 1번, 네트워크 연결됨(research R14·R15) | 바뀐 것이 있을 때만(일기·사진·설정이 마지막 성공 뒤 바뀜). 마지막 백업이 드라이브에서 없어졌으면 바뀐 것이 없어도 전부 |
| 앱을 열 때 | 마지막 성공이 24시간 넘음, 자동 백업 켬, 이전·복원 중 아님 | 자동과 같다(FR-015) |

- 한 번에 하나만 돈다. 복원이나 이전이 도는 동안에는 백업하지 않는다.
- 일기 쓰기·읽기를 막지 않는다. 스냅샷은 그 순간을 뜨고, 그 뒤 쓴 일기는 다음 백업에 들어간다(FR-012).
- 사진은 기본으로 Wi-Fi(데이터 요금이 없는 연결)에서만 올린다. 모바일 데이터면 사진 없이 스냅샷과 목록 파일만 올리고, 못 올린 사진은
  `inBackup=false`로 적는다. 다음 Wi-Fi 백업에서 올린다(FR-014).
- 실패하면 몇 번 조용히 다시 해 본다(드라이브가 잠깐 거절, 서버 오류는 지수적으로 늦춰 다시). 그래도 안 되면 상태에 까닭을 남기고 다음 기회를 기다린다.

## 실패의 종류

| 종류 | 언제 | 사용자에게 |
| --- | --- | --- |
| `AUTH` | 토큰을 받을 수 없음, 권한 취소, 계정 없음 | 상태 "다시 연결이 필요해요", [다시 연결] |
| `NO_SPACE` | 드라이브 공간 부족 | 부족한 양, 정리 방법, 구글 저장 공간 화면, 묶음 파일(FR-019) |
| `OFFLINE` | 네트워크 없음, 끊김 | 다음 기회에 이어서. 7일이 넘기 전에는 알리지 않는다 |
| `DRIVE_ERROR` | 드라이브가 계속 거절(속도 제한, 서버 오류, 알 수 없는 4xx) | 다음 기회에 이어서 |
| `LOCAL_IO` | 기기 공간 부족으로 스냅샷을 못 뜸, 파일 읽기 실패 | 기기 공간을 비워 달라는 안내 |
| `UNKNOWN` | 그 밖 | 다음 기회에 이어서 |

## 상태 표시

홈 머리의 상태 줄(`caption`, 아이콘과 짝)과 설정 > 백업 맨 위가 같은 상태를 보인다. 문구는 문자열 리소스이고 다듬기는 디자인 단계에서 한다.

| 상태 | 홈 상태 줄 예 | 설정 > 백업 |
| --- | --- | --- |
| 연결 안 함 | "백업 꺼짐 · 켜기" | "구글 드라이브에 일기와 사진을 백업해요" + [연결하기] |
| 도는 중 | "백업 중 · 사진 120/860" | 진행 막대, 단계 이름 |
| 성공, 사진 다 | "마지막 백업 오늘 오후 9:30" | "사진 1,203장 모두 백업됨" |
| 성공, 사진 남음 | "마지막 백업 오늘 오후 9:30 · 사진 3장 대기" | 까닭(Wi-Fi 대기, 공간 부족)과 할 일 |
| 하루 넘게 실패 | "마지막 백업 3일 전" | 까닭과 할 일 |
| 7일 넘게 실패 | "마지막 백업 8일 전"과 빨간 점(알림이 꺼져 있을 때, FR-016) | 까닭과 할 일 |
| 다시 연결 필요 | "다시 연결이 필요해요" | [다시 연결] |

- 보이는 시각은 목록 파일까지 확인한 마지막 성공 시각이다. 시도한 시각이 아니다(US4 시나리오 3).
- 진행 숫자는 30초 넘게 멈춰 보이지 않게 바이트 단위로도 나아간다(SC-005).

## 알림

- Android 채널 "백업"(중요도 기본). iOS는 로컬 알림. 알림 허용이 없으면 보내지 않고 홈의 빨간 점으로 대신한다.
- 7일 넘게 성공하지 못하면 한 번 보낸다(FR-016). 다시 성공할 때까지 또 보내지 않는다. 누르면 설정 > 백업으로 간다.
- 바뀐 것이 없어 올리지 않은 날(`Unchanged`)도 백업은 잘 되는 중이라 알림을 그날부터 7일 뒤로 민다. 자동 백업을 끄거나 연결을 끊으면 알림을 걸지 않고 대기 중인 것도 지운다(2026-11-07).
- 본문은 실패 종류에 맞춘 한 문장이다. 일기 내용, 사진, 개수는 넣지 않는다.
- 지금 백업과 복원이 백그라운드에서 이어질 때 진행 알림을 보일 수 있다(research R14). 진행 알림에도 일기 내용은 없다.
- 연결하지 않은 사람에게 연결을 권하는 알림은 보내지 않는다(FR-036).

## 권하기 카드 (FR-036)

보일 조건(모두 참):

- 연결 안 함(`account_key` 없음), `user_disconnected=false`
- `nudge_dismiss_count < 3`, `nudge_hidden_until`이 없거나 지남
- 이전한 사용자(이전 결과가 있음)이거나, 일기가 3편 이상이거나, 사진이 든 일기가 1편 이상
- 지금 화면이 홈이다. 쓰기·읽기·잠금·이전·복원 화면에는 없다

동작:

- [백업 켜기] → 연결 흐름. 이전한 사용자는 옛 백업 계정(`legacy_backup_account`)을 먼저 보인다(Android).
- [나중에] → `nudge_dismiss_count += 1`, `nudge_hidden_until = 지금 + 14일`.
- 숫자는 지금 기기의 일기 수(휴지통 제외)와 사진 수다.

## 사용 통계 고정 표 더하기 (`AnalyticsEvents`, 스펙 001 `contracts/app-shell.md`)

값은 열거형과 개수 구간(스펙 001 `AnalyticsEvents.COUNT_BUCKETS`)뿐이다. 일기 내용, 사진, 장소, 기분, 드라이브 파일 이름·ID, 계정은 보내지 않는다(FR-032).

| 이벤트 | 값 |
| --- | --- |
| `backup_connect` | `result`(`ok`·`cancel`·`error`), `from`(`settings`·`nudge`·`onboarding`·`legacy`) |
| `backup_run` | `trigger`(`manual`·`auto`·`app_open`), `result`(`ok`·`partial_photos`·`failed`), `failure`(실패의 종류), `photos_uploaded`(구간), `duration_bucket`(스펙 001 시간 구간) |
| `restore_run` | `source`(`drive`·`file`·`legacy_drive`), `mode`(`merge`·`replace`), `result`(`ok`·`cancel`·`failed`), `failure`, `entries`(구간), `kept_both`(구간), `photos_missing`(구간) |
| `backup_rollback` | `result`(`ok`·`failed`·`expired`) |
| `backup_nudge` | `action`(`shown`·`accept`·`dismiss`) |
| `backup_export` | `kind`(`export`·`import`), `result`, `photos`(구간) |

오류 보고(Crashlytics)에는 `BackupError(kind, step)`로 바꾼 뒤 보낸다. 드라이브 응답 본문, 파일 이름, 경로가 든 예외 메시지는 보내지 않는다.

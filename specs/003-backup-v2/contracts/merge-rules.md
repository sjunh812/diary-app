# 합치기·바꾸기·되돌리기 규칙

복원(드라이브, 묶음 파일)과 이전 버전 백업 불러오기가 지금 기기 기록과 백업을 어떻게 합치는지 정한다. 표와 열은 [data-model.md](../data-model.md),
근거는 [research.md](../research.md) R11~R13이다. 이 규칙의 시험은 `shared/core/backup/src/commonTest`의 합치기 표 시험이 그대로 옮긴다.

## 공통

- 지금 기기의 일기는 합치기에서 하나도 지우지 않는다(헌법 I, FR-022).
- 받은 스냅샷은 목록 파일의 확인값과 일기 수를 맞춘 뒤에만 연다(FR-021). 열 때는 읽기 전용으로 연다.
- 미리보기(FR-023)는 아래 규칙을 쓰기 없이 돌려 센 값이다. 사용자가 확인하면 같은 규칙을 **한 트랜잭션**으로 쓴다. 중간에 실패하면 아무것도 바뀌지 않는다.
- 사진 파일은 트랜잭션이 끝난 뒤 받는다. 그동안 사진 줄은 `pending`이다.
- 사용 통계에는 단계, 개수 구간, 실패 종류만 보낸다(FR-032).

## 드라이브·묶음 파일 합치기 (기본)

백업의 일기 B와 지금 기기의 같은 `id` 일기 L, L의 `sync_base` 값 S(없을 수 있음)로 가른다.

| 경우 | 조건 | 결과 | 미리보기 칸 |
| --- | --- | --- | --- |
| 1 | L 없음 | B를 더한다 | 더해질 일기 |
| 2 | `L.updated_at == B.updated_at`, 내용이 같음 | 그대로 | 같은 일기 |
| 3 | S 있음, `B.updated_at <= S` | L을 둔다(백업이 이미 맞춰 본 것이거나 더 옛것) | 같은 일기 |
| 4 | S 있음, `L.updated_at == S`, `B.updated_at > S` | L을 B로 바꾼다(이 기기는 그 뒤로 안 고침) | 바뀔 일기 |
| 5 | S 있음, `L.updated_at > S`, `B.updated_at > S` | 둘 다 남긴다. L은 그대로, B는 새 `id`로 더하고 둘 다 `merge_mark(kept_both)` | 둘 다 남길 일기 |
| 6 | S 없음, `L.updated_at != B.updated_at` | 더 늦게 고친 쪽을 남긴다. 늦은 쪽이 B면 바꾼다 | 바뀔 일기 또는 같은 일기 |
| 7 | `updated_at`이 같은데 내용이 다름(시계가 틀린 기기) | 경우 5처럼 둘 다 남긴다 | 둘 다 남길 일기 |

- "내용"은 `date`, `time`, `body_html`, `mood`, `weather`, `place_name`, `is_favorite`, `deleted_at`, 사진 줄(순서, `sha256`, `status`)이다.
- L을 B로 바꿀 때는 L의 사진 줄을 B의 사진 줄로 바꾼다. 기기의 사진 파일은 지우지 않는다(정리는 스펙 002 규칙이 나중에 한다).
- 경우 5·7에서 새로 더하는 B의 사진 줄도 새 `id`를 받고 같은 `sha256`을 가리킨다. 파일은 하나다.
- 끝나면 더하거나 바꾼 일기의 `sync_base`를 B의 `updated_at`으로 쓴다. 경우 5의 L은 `sync_base`를 그대로 둔다.
- 영구 삭제한 일기의 흔적(묘비)은 두지 않는다. 기기에서 영구 삭제한 일기가 백업에 있으면 경우 1로 다시 생긴다. 지우는 쪽으로 틀리는 것보다
  남기는 쪽으로 틀린다(헌법 I, research R11).

### 휴지통

- `deleted_at`도 내용이라 위 표를 그대로 따른다. 백업에서 휴지통에 있던 일기는 기기에서도 휴지통에 남은 날짜와 함께 들어간다.
- 받은 일기의 휴지통 남은 날이 하루보다 적으면 복원한 날부터 7일을 준다(`deleted_at`을 그만큼 당긴다). 옛 백업에서 지운 일기를 찾으러 온 사람이
  복원 직후 자동 비움으로 다시 잃지 않게 한다.

### 사진 줄

| 백업의 사진 줄 | 기기에 같은 `sha256` 파일 | 목록 파일에서 | 들어갈 상태 |
| --- | --- | --- | --- |
| `normal` | 있음 | 상관없음 | `normal` |
| `normal` | 없음 | 백업에 있음 | `pending` → 받고 확인값이 맞으면 `normal`, 다르면 `missing` |
| `normal` | 없음 | 백업에 없음(공간 부족으로 못 올림) | `pending`으로 남고 "원래 기기에 있는 사진"으로 보인다 |
| `pending` | 있음/없음 | 위와 같음 | 위와 같음 |
| `missing` | - | - | `missing`, `legacy_path` 그대로 |

같은 일기에 이미 `pending`인 줄이 있고 이번 백업에 그 파일이 있으면 받는다. 일기가 경우 2·3이라 바뀌지 않아도 사진은 채운다.

### 설정

- 글꼴, 본문 글자 크기, 화면 모드, 매일 알림(켬·시각), 목록 모양, 즐겨찾기만 보기, 장소 다시 묻기는 백업 값으로 바꾼다(FR-026). 미리보기에 "설정도
  백업 때 값으로 바뀌어요"를 보인다. 알림은 다시 예약한다.
- 잠금은 꺼진 채로 둔다. 백업한 기기에서 잠금이 켜져 있었으면(`settings.lockEnabled`) 끝난 뒤 "잠금을 다시 정해 주세요"를 한 번 보인다.
- 백업 설정(`backup.preferences_pb`), 옛 드라이브 백업 연결 값은 바꾸지 않는다.

### 형식 버전

- 목록 파일의 `formatVersion`이 앱이 아는 것보다 크거나 스냅샷의 DB 버전이 앱보다 높으면 "앱을 업데이트하면 되살릴 수 있어요"로 보이고 고를 수 없다.
- 낮은 버전은 읽는다(FR-035). 버전마다 옮기는 코드는 `shared/core/backup`의 `SnapshotReader`가 갖는다.

## 이전 버전 백업(1.7.x `note.db`) 합치기

값은 `docs/migration.md` "옮겨 담기"와 스펙 001 `contracts/legacy-mapping.md`를 그대로 쓴다. 레거시 줄 하나를 새 일기 후보 C로 바꾼 뒤 가른다.

| 경우 | 조건 | 결과 |
| --- | --- | --- |
| 1 | 기기에 `date`, `time`, `plain_text`가 모두 같은 일기가 있음 | 더하지 않는다(같은 일기). 기기 일기는 그대로 |
| 2 | 기기에 `date`, `time`이 같고 글이 다른 일기가 있음 | C를 더하고 둘 다 `merge_mark(legacy_same_time)` |
| 3 | 그 밖 | C를 더한다 |

- `legacy_id`로는 견주지 않는다. 다른 기기의 `note.db`면 같은 번호가 다른 일기다.
- 이 기기에서 이미 이전한 일기는 경우 1로 걸러진다(US3 시나리오 5).
- 사진: 레거시 경로에 파일이 이 기기에 있으면(Android만) 스펙 001 이전과 같은 방법으로 `media/`에 복사해 `normal`, 없으면 `missing`과 `legacy_path`.
  iOS에서는 모두 `missing`이다. 미리보기에 "예전 백업에는 사진이 없어요"를 보인다(FR-030).
- 더한 일기에는 `sync_base`를 쓰지 않는다.
- 예전 백업은 WAL 없이 올라가 최근 일기가 빠졌을 수 있다. 들어 있는 만큼만 되살리고 미리보기에 그 사실을 알린다.

## 바꾸기 (따로 고르는 선택지)

1. 기기 공간을 본다. 되돌리기 사본(DB 크기 + 설정)이 들어갈 자리가 없으면 바꾸기를 시작하지 않는다.
2. 지금 DB를 `rollback/<시각>/diary.db`로 `VACUUM INTO`, 지금 설정을 `settings.json`으로 쓴다. 사본을 열어 일기 수와 무결성을 확인한다.
3. 한 트랜잭션으로 `entry`, `media`, `sync_base`, `merge_mark`를 비우고 백업의 일기와 사진 줄을 넣는다. 임시 저장본은 건드리지 않는다.
4. `rollback_until = 지금 + 7일`. 그때까지 사진 정리(스펙 002)를 멈춘다. 바꾸기 전 일기가 가리키던 사진 파일이 남아 있어야 되돌릴 수 있다.
5. 사진은 합치기와 같은 방법으로 받는다.

## 되돌리기 (바꾸기 뒤 7일 안)

1. 되돌리기 사본을 열어 확인한다.
2. 한 트랜잭션으로 바꾸기 전 일기와 사진 줄을 되살린다.
3. 바꾸기 뒤에 새로 쓰거나 고친 일기(`updated_at`이 바꾼 시각보다 늦음)는 지우지 않고 위 "드라이브·묶음 파일 합치기" 규칙으로 함께 남긴다.
4. 설정을 `settings.json` 값으로 되돌리고 사본을 지우고 `rollback_until`을 지운다. 사진 정리를 다시 켠다.
5. 7일이 지나면 사본을 지우고 사진 정리를 다시 켠다. 지우기 하루 전에 설정의 백업 화면에 "내일까지 되돌릴 수 있어요"를 보인다.

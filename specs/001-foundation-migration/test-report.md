# 업그레이드 시험 기록 (T051)

1.7.4(`94179a4`) → 새 앱(2.0.0, 37) 업그레이드를 에뮬레이터에서 돌린 기록이다. 돌리는 법은 `scripts/legacy/upgrade-test.sh`.
아래 기록이 강제 종료, 계측 시험, 1,000편·사진 1,000장 시간 재기다. API 24·29·35·36에서 돌렸다. quickstart §2의 나머지 견본(wal-only,
restored-from-drive, low-space, corrupt, locked, fonts)은 아직이다(못 한 것 참고).

## 2026-11-01 (2) · 강제 종료, 계측 시험, 큰 견본

## 2026-11-02 · API 24·29

Google 공식 SDK 저장소에서 Google APIs arm64 이미지(API 24 rev 29, API 29 rev 13)를 받아 SHA-1을 맞춰 보고 돌렸다(사용자 허락).
처음 API 26·31이 멈춘 것은 폰 설정 파일을 통째로 베낀 탓으로 보인다. 필요한 항목만 적은 설정으로는 API 24·29가 바로 켜졌다.

| 기기 | 조합 | 원본 해시 | 새 DB | 이전 시간 | 계측 시험 |
| --- | --- | --- | --- | --- | --- |
| API 24 폰(한국어) | 기본, `KILL_AT` 네 단계 | 그대로 | 일기 4, 사진 normal 3·missing 1 | 0.03~0.05초 | 모두 통과 |
| API 24 폰 | `COUNT=1000` | 그대로 | 일기 1,004, 사진 normal 1,003·missing 1 | 2.3초 | 통과 |
| API 29 폰 | 기본, `KILL_AT=Copying`, `KILL_AT=Committing` | 그대로 | 같음 | 0.05~0.07초 | 모두 통과 |
| API 29 폰 | `COUNT=1000` | 그대로 | 일기 1,004, 사진 normal 1,003·missing 1 | 2.2초 | 통과 |

- **고친 결함**: 처음 API 24에서는 새 앱이 켜자마자 꺼졌다. kotlinx-datetime이 Android 8부터 있는 `java.time`을 쓰는데 Java 표준 라이브러리
  desugaring을 켜지 않았기 때문이다(`NoClassDefFoundError: java.time.ZoneOffset`). 앱 모듈 설정에서 켜고 다시 돌려 통과했다. Android 7 기기의
  예전 사용자는 이 수정이 없었으면 업데이트 직후 앱을 열 수 없었다.
- **한국어 줄바꿈**: Android 12 이하에는 구절 단위 줄바꿈이 없어 결과 화면에서 "날/짜"처럼 낱말 가운데서 줄이 바뀐다. 설계 때 알던 제약이다
  (`docs/design.md` 여러 언어, Android 13 이상만 구절 단위).
- 업그레이드 시험의 원본 해시는 이제 기기에서 꺼내 이 컴퓨터에서 잰다. API 24에는 기기 쪽 `sha256sum`이 없다.
- 같은 에뮬레이터에 시험을 둘 겹쳐 돌리면 서로 견본을 다시 넣어 "원본 해시가 바뀌었어요"가 나온다. 한 기기에는 한 번에 하나만 돌린다.

### 못 한 것

- API 26·31: 위 설정으로는 다시 시도하지 않았다. 24·29·35·36으로 가장 낮은 버전부터 최신까지 걸쳤다.
- quickstart §2의 wal-only, restored-from-drive, low-space, corrupt, locked, fonts 견본은 `seed.sh`에 아직 없다.
  같은 경우를 `shared/core/migration`의 공통 시험(MigrationRunnerTest 등)이 견본 파일로 본다.

- iOS 시뮬레이터에서 잠금 화면과 가림 창(`PrivacyCover.swift`)은 아직 없다.

## 2026-11-02 (3) · 매일 알림(US3, FR-022)

API 29 에뮬레이터(한국어)에서 1.7.4에 알림 21:30을 켜 두고(`ALARM=1`) 앱을 강제 종료하지 않은 채 새 APK로 덮어 설치했다. 새 앱은 열지 않았다.

- 업데이트 알림(`MY_PACKAGE_REPLACED`)으로 수신기가 돌아 옛 설정을 옮기고 그날 21:30(KST)에 `RTC_WAKEUP` 예약을 걸었다(`dumpsys alarm`, 창 10분).
- 수신기를 직접 불러(루트 셸) 알림을 띄웠다: 채널 `alarm_id`, 연필 작은 아이콘, "오늘 하루는 어땠나요? 한 줄만 남겨 보세요." 앱은 멈추지 않았다.
- 시험하면서 `am force-stop`으로 앱을 멈춰 둔 상태(`stopped=true`)에서는 시스템이 업데이트 알림을 보내지 않아 예약이 걸리지 않았다.
  사용자가 강제 종료하지 않았다면 해당하지 않고, 앱을 한 번 열면 다시 예약한다.

## 2026-11-02 (4) · 비밀번호를 잊어버렸을 때(US2, FR-019)

API 36 에뮬레이터(한국어)에 시험용 휴대폰 PIN을 걸고(`adb shell locksettings set-pin`) 잠긴 앱에서 확인했다. 끝난 뒤 PIN은 지웠다.

- "비밀번호를 잊어버렸어요" → 시트 "휴대폰 잠금으로 확인할게요" → [확인하기] → 시스템 인증 창(BiometricPrompt, 폰 PIN) → PIN 입력 →
  새 비밀번호 정하기 → "한 번 더 입력해 주세요" → 열림. 폰 PIN 창을 다녀오는 동안 다시 잠기지 않았다.
- 앱을 새로 열면 잠금 화면이 뜨고, 옛 비밀번호는 "비밀번호가 맞지 않아요 · 남은 횟수 4번", 새 비밀번호는 열렸다.
- 잠금 설정(개발 빌드 화면 모음 `lock_settings`)에서 잠금 켜기(새 비밀번호 두 번)도 확인했다.
- 5번 틀린 뒤 "27초 뒤에 다시 입력할 수 있어요"가 뜨고, 앱을 강제 종료했다가 다시 열어도 "잠시 기다려 주세요"와 남은 초가 이어졌다.
  기다리는 동안에는 맞는 비밀번호도 받지 않았다.
- 개발 빌드는 에뮬레이터에서 첫 화면이 그려지기까지 몇 초 걸려 그동안 시스템 시작 화면이 보인다. 시작 화면과 성능은 US4(T030·T083)에서 잰다.

## 2026-11-02 (5) · 시작 화면과 옛 런처 이름(US4)

## 2026-11-03 (2) · 시작 화면(US4)과 잠긴 채 업데이트한 뒤 매일 알림(US3)

- API 29 에뮬레이터는 `cmd uimode night yes`가 막혀 있어(`mNightModeLocked=true`) 설정 > 디스플레이 > 어두운 테마로 바꿨다.

- 업데이트 알림으로 수신기가 돌아 `org.sjhstudio.diary/.helper.AlarmReceiver`에 다음 날 21:30(KST) `RTC_WAKEUP`, 창 10분 예약을 걸었다.
- 수신기를 불러(루트 셸) 알림을 띄웠다. 채널 `alarm_id`, 제목 "1일 1일기", 본문 "오늘 하루는 어땠나요? 한 줄만 남겨 보세요.", 비공개 알림(`vis=PRIVATE`). 앱은 멈추지 않았다(`AndroidRuntime` FATAL 0건).
- 알림을 누르면 잠금 화면이 먼저 뜨고, 잠긴 동안 `files/migration`과 `files/legacy-snapshot`은 비어 있다(이전을 시작하지 않음).
- `seed.sh`는 견본을 넣은 뒤 앱을 강제 종료한다. 그대로 덮어 깔면 시스템이 업데이트 알림을 보내지 않아 예약이 걸리지 않으니, 시험할 때는 옛 앱을 한 번 더 연다.

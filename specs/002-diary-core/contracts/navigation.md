# 화면 전환 계약

화면 키와 뒤로 가기, 창 폭별 배치를 정한다. 키는 `shared/app`이 갖고 기능 모듈은 진입 컴포저블만 내놓는다.

## 화면 키

| 키 | 화면 | 인자 |
| --- | --- | --- |
| `Home` | 홈 목록 (S1) | 없음 |
| `EntryDetail(entryId)` | 상세 (S3) | 일기 ID |
| `PhotoViewer(entryId, index)` | 사진 크게 (S3-a) | |
| `Write(target)` | 쓰기·수정 (S2) | `New(date?)` 또는 `Edit(entryId)` |
| `Calendar(yearMonth?)` | 달력 (S4) | |
| `Search(filter?)` | 검색 (S1-a) | 통계에서 오면 조건이 채워져 있다 |
| `Insight` | 기분 통계 (S5) | |
| `Trash` | 휴지통 (S6-7) | |
| `ListStyleSettings` | 설정 > 목록 모양 | |

코드의 키 이름은 뒤에 `Key`가 붙는다(`EntryDetailKey`). 달력은 달을 키에 두지 않고 화면 안에서 넘긴다. `Search`는 기분과 기간만 키에 담는다.

하단 탭(폰)과 레일(600dp 이상)의 항목은 홈, 달력, 돌아보기(통계), 설정 넷이고 쓰기 버튼은 늘 보인다. 레거시는 쓰기가 탭이었다.

## 뒤로 가기

- 탭 안 화면에서 뒤로 가면 그 탭의 첫 화면, 첫 화면에서 뒤로 가면 홈, 홈에서 뒤로 가면 앱을 닫는다(Android 시스템 기본, 레거시의 "두 번 눌러 종료"는 쓰지 않는다).
- 탭마다 화면을 따로 쌓는다(공식 nav3-recipes `multiplestacks`). 탭을 옮겼다 와도 그 탭의 스크롤, 화면 모델, 쌓인 화면이 그대로이고, 앱이 죽었다 살아나도 쌓인 화면과 고른 탭은 되살아난다. 지금 탭을 다시 누르면 그 탭의 첫 화면으로 간다.
- 다른 화면이 탭을 열 때(백업 상태 줄, 글꼴 안내, 복원을 마친 뒤 홈)는 그 탭의 첫 화면에서 시작한다.
- 탭을 옮길 때는 두 화면을 겹치지 않고 바로 바꾼다.
- 쓰기에서 뒤로 가면 임시 저장 뒤 들어온 곳으로(FR-011).
- 검색 → 상세 → 뒤로 가면 검색 화면이 입력·조건·스크롤 그대로(FR-027).

## 창 폭별 배치

| 폭 | 홈 | 달력 | 쓰기 |
| --- | --- | --- | --- |
| 600dp 미만 | `Home` 한 칸, 줄을 누르면 `EntryDetail`로 쌓임 | 달력 아래 그날 목록 | 전체 화면 |
| 600~839dp | 위와 같고 레일 | 위와 같고 레일 | 전체 화면 |
| 840dp 이상 | `Home`이나 `Search` 왼쪽 + `EntryDetail` 오른쪽(고른 게 없으면 안내) | 달력 왼쪽 + 그날 목록 오른쪽 | 본문 가운데 + 옆 칸(기분·날씨·장소·사진) |

- 두 칸에서 고른 상세는 뒤로 쌓지 않고 오른쪽만 바꾼다. 폭이 좁아지면 그 상세가 한 칸으로 쌓인 상태로 바뀐다(FR-037).
- 두 칸에서 상세를 지우면 오른쪽은 안내 문구로 돌아간다.
- 뒤로 버튼은 상세가 실제로 목록 옆에 그려질 때만 뺀다. 달력에서 연 상세는 넓은 화면에서도 한 칸이라 뒤로 버튼이 있다.

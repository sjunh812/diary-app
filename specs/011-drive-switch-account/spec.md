# 기능 명세: 백업 구글 계정 변경

**스펙**: `011-drive-switch-account`
**브랜치**: `feat/drive-switch-account`
**작성**: 2026-11-22
**상태**: 초안
**입력**: 사용자 요청 2026-11-22 "드라이브 연동된 상태에서 구글 계정 바꾸기 기능 추가, 해제 후 연동해도 최초 연동한 계정으로만 자동 연동돼서". 사용자가 확정한 안(같은 날): 백업 설정의 [구글 계정] 줄을 눌러 바꿈(프로토타입에서 안 B), 확인 창 없이 바로 계정 선택, 바꾸면 처음 연결과 같은 흐름, 백업·복원 중에는 막음, 취소·실패면 이전 연결 유지, 저장 형식·백업 형식은 그대로.

## 근거

- **원인(재현함)**: Android는 연결을 끊을 때 이 기기에 둔 계정 이메일만 지우고 구글 쪽 권한은 그대로 둔다(`docs/DECISIONS.md` 2026-11-06 "구글 권한은 거두지 않는다"). 구글 권한 받기는 이미 허락한 계정이 있으면 계정 고르기를 건너뛴다([Android 권한 받기](https://developer.android.com/identity/authorization)). 그래서 [구글 드라이브 연결하기]를 눌러도 계정 선택 창 없이 처음 계정으로 붙는다. 2026-11-22 Android 12 에뮬레이터에서 연결 → 연결 끊기 → 연결하기 순서로 재현했다.
- **iOS는 이 문제가 없다**: 같은 날 iPhone 17 시뮬레이터에서 이미 권한을 준 계정("이미 일부 액세스 권한이 있음")으로 연결해도 구글 "계정을 선택하세요." 화면이 먼저 떴다.
- **고치는 길**: 구글이 권한 요청에 "계정 고르기를 띄워라"는 값을 공식으로 준다([AuthorizationRequest.Prompt](https://developers.google.com/android/reference/com/google/android/gms/auth/api/identity/AuthorizationRequest.Prompt), play-services-auth 21.5.0부터, 우리는 22.0.0). 이 값을 넣은 시험 빌드에서 끊은 뒤 다시 연결할 때 "계정 선택" 창이 떴고, 같은 계정을 고르면 드라이브의 기존 백업이 그대로 보였다. 권한을 거두는 길은 쓰지 않는다. 권한을 거둔 뒤 다시 받으면 앱이 만든 백업 파일에 다시 닿는지 공식 문서에 없고, 비공식 보고는 "안 보인다" 쪽이다(헌법 I).
- **레퍼런스**(공식 도움말에서 확인한 것만, 2026-11-22):
  - WhatsApp: 채팅 백업 화면의 "Google Account"에서 계정을 바꾸고, 백업은 사용자가 [Back up]을 눌러 한다([도움말](https://faq.whatsapp.com/481135090640375/?locale=en_US)).
  - Daylio: 백업·복원 화면 맨 아래 [Log Out] 뒤 새 계정으로 로그인한다. 바꾸기 전에 이전 계정에 한 번 더 백업하라고 권한다([도움말](https://daylio.net/faq/docs/daylio-faq/backup/switch-google-accounts-for-backups/)).
  - LINE: 계정을 고르면 그 계정의 마지막 백업 날짜와 크기를, 없으면 "No data found"를 보인다([도움말](https://help.line.me/line/smartphone/?contentId=20023473)).
  - 확인한 곳 모두 계정을 바꿀 때 이전 계정의 백업을 지우지 않는다. 바꾸기 전 확인 창은 어느 도움말에도 없다.
- 우리 앱은 이미 "다른 계정으로 연결하면 앞 계정의 백업 기록을 지우고 자동 백업 값은 지킨다"를 갖고 있다(스펙 003 엣지 케이스 "다른 구글 계정으로 연결", `BackupController`). 이 스펙은 그 흐름에 들어가는 문을 연결된 상태에서도 열고, Android의 계정 고르기를 고친다.

## Clarifications

### 2026-11-22 세션

- Q: 바꾸기 전에 확인 창을 띄우나? → A: 띄우지 않는다. 드라이브에서 지우는 것이 없고, 구글 계정 선택 창에서 취소할 수 있다(사용자 확정).
- Q: 새 계정으로 바꾼 뒤에는? → A: 처음 연결과 같다. 그 계정 드라이브에 백업이 있으면 "구글 드라이브에 백업이 있어요"로 합치기를 권하고, 없으면 바로 첫 백업을 한다(사용자 확정).
- Q: 백업이나 복원이 도는 중에는? → A: 바꾸지 않는다. 두 계정의 백업이 섞이지 않게 한다(사용자 확정). 줄을 누르면 까닭을 토스트로 알린다(안 B에 맞춤).
- Q(프로토타입): 계정 변경을 따로 한 줄(안 A)로 둘까, [구글 계정] 줄을 누르게(안 B) 할까? → A: 안 B. Figma B13 설명(2026-11-01)의 "구글 계정(누르면 계정 바꾸기)"와 같다(사용자 확정 2026-11-22).
- Q: 연결을 끊었다 다시 이을 때나 "다시 연결이 필요해요"에서 이을 때도 계정을 고르나? → A: 고른다. 두 플랫폼이 같게 계정 선택 창을 띄운다. 예전 앱이 쓰던 계정을 먼저 보이는 홈 카드(스펙 003 US4 시나리오 8)는 그대로 둔다(사용자 확정).

## 사용자 시나리오

### US1 - 끊었다 다시 이을 때 계정을 고른다 (P1)

드라이브 연결을 끊고 다시 [구글 드라이브 연결하기]를 누르면, Android에서도 iOS처럼 구글 계정 선택 창이 뜬다. 처음에 쓴 계정이 아닌 다른 계정을 고를 수 있다.

**왜 P1인가**: 지금 Android 사용자는 다른 계정으로 백업할 길이 없다. 사용자가 보고한 버그다.

**독립 시험**: 구글 계정이 있는 에뮬레이터에서 연결 → [연결 끊기] → [구글 드라이브 연결하기]를 누른다.

1. **Given** 연결했다가 끊은 Android 기기, **When** [구글 드라이브 연결하기]를 누르면, **Then** 구글 계정 선택 창이 뜬다.
2. **Given** 계정 선택 창, **When** 처음과 같은 계정을 고르면, **Then** 다시 허용을 묻지 않거나 한 번 묻고 연결되며, 그 계정 드라이브의 기존 백업이 그대로 보인다.
3. **Given** 계정 선택 창, **When** 다른 계정을 고르면, **Then** 그 계정으로 연결되고 처음 연결과 같은 흐름(백업 찾기 → 합치기 권하기 또는 첫 백업)이 이어진다.
4. **Given** 계정 선택 창, **When** 취소하면, **Then** 연결하지 않은 채로 남고 아무 안내도 뜨지 않는다.
5. **Given** "다시 연결이 필요해요" 상태, **When** [다시 연결]을 누르면, **Then** 계정 선택 창이 뜬다(두 플랫폼 같음).
6. **Given** 예전 앱에서 드라이브 백업을 쓰다 이전한 Android 사용자, **When** 홈 카드의 [백업 켜기]를 누르면, **Then** 지금처럼 그 계정을 먼저 보여 준다.

---

### US2 - 연결된 채로 백업 계정을 바꾼다 (P1)

백업 설정의 "계정" 묶음에서 [구글 계정] 줄(이메일 옆 화살표)을 누르면 바로 구글 계정 선택 창이 뜬다. 다른 계정을 고르면 그 계정 드라이브에 백업한다. 이전 계정의 백업은 드라이브에 그대로 남는다.

**왜 P1인가**: 요청의 본론이다. 지금은 끊었다 다시 이어야 하고, Android는 그마저 같은 계정으로 붙는다.

**독립 시험**: 구글 계정 두 개가 있는 기기에서 계정 A로 연결해 백업한 뒤 [구글 계정] 줄을 눌러 계정 B를 고른다.

1. **Given** 계정 A로 연결됨, **When** 백업 설정에서 [구글 계정] 줄을 누르면, **Then** 확인 창 없이 구글 계정 선택 창이 뜬다.
2. **Given** 계정 선택 창, **When** 계정 B를 고르고 B의 드라이브에 백업이 없으면, **Then** "구글 계정"에 B가 보이고 B의 드라이브로 첫 백업이 시작된다.
3. **Given** 계정 선택 창, **When** 계정 B를 고르고 B의 드라이브에 다른 기기의 백업이 있으면, **Then** "구글 드라이브에 백업이 있어요"가 뜨고, 사용자가 고르기 전에는 올리지 않는다.
4. **Given** 계정 B로 바꿈, **Then** 계정 A 드라이브의 "1일 1일기 백업" 폴더와 파일은 그대로다. 이 기기에서는 A의 마지막 백업 시각, 실패 기록 같은 백업 기록만 지운다.
5. **Given** 자동 백업을 꺼 둔 채 계정 B로 바꿈, **Then** 자동 백업은 꺼진 채로 남는다. 켜 둔 사람은 켜진 채로 남는다.
6. **Given** 계정 선택 창, **When** 계정 A를 다시 고르면, **Then** 아무것도 바뀌지 않는다. 마지막 백업 기록도 그대로다.
7. **Given** 계정 선택 창, **When** 취소하면, **Then** 계정 A 연결이 그대로이고 아무 안내도 뜨지 않는다.
8. **Given** 계정 선택 창, **When** 인터넷이 끊겼거나 구글이 실패를 알리면, **Then** 계정 A 연결이 그대로이고 지금의 "구글 드라이브에 연결하지 못했어요" 안내가 뜬다.
9. **Given** 백업이 올라가는 중이거나 복원이 도는 중, **When** [구글 계정] 줄을 누르면, **Then** 계정 선택 창을 띄우지 않고 "백업이나 복원이 끝나면 바꿀 수 있어요." 안내만 잠깐 보인다.

---

### Edge Cases

- **iOS에서 드라이브 권한을 빼고 허용**: 새 계정 B로 계정 선택은 했지만 동의 화면에서 드라이브 권한을 빼면 연결 실패로 알린다. GoogleSignIn은 고르는 순간 로그인을 B로 바꿔 계정 A 로그인은 남지 않는다. 그래서 실패한 뒤 A 연결이 살아 있는지 확인하고, 없으면 바로 "다시 연결이 필요해요"로 보인다. 드라이브의 백업은 건드리지 않는다.
- **Android에서 드라이브 권한을 빼고 허용**: 지금처럼 "드라이브 권한이 없어요" 실패로 알리고 이 기기에 둔 계정 A를 그대로 둔다.
- **바꾼 직후 앱을 닫음**: 다음에 열면 새 계정 B로 이어서 보인다. 찾은 백업 안내가 떠 있던 중이면 다시 연다(스펙 003 "찾은 백업" 규칙).
- **바꾸는 사이 자동 백업이 깨어남**: 계정을 고르는 동안(화면이 떠 있는 동안)에는 이 기기에 아직 A가 있으므로 A로 올리고, B로 바뀐 뒤에 깬 작업은 B로 올린다. 한 번의 백업이 두 계정에 걸쳐 올리지 않는다.
- **이어 올리기가 남은 상태에서 바꿈**: A에서 끊긴 큰 파일 올리기는 B에서 잇지 않고 처음부터 한다.
- **복원 목록**: 바꾼 뒤 복원 화면에는 B의 백업만 보인다. A의 목록을 먼저 보이지 않는다(2026-11-14 결정 "다른 계정의 목록은 먼저 보이지 않는다").
- **7일 실패 알림**: A 기준으로 걸어 둔 알림은 지우고, B로 첫 백업이 성공하면 다시 건다. 자동 백업을 꺼 둔 사람은 걸지 않는다.
- **연결 끊긴 상태("다시 연결이 필요해요")**: [구글 계정] 줄에 연결했던 이메일이 보이고, 누르면 [다시 연결]과 같은 계정 선택 창이 뜬다.
- **기기에 구글 계정이 하나뿐**: 계정 선택 창에 그 계정과 "다른 계정 추가"가 보인다. 계정 추가는 구글 화면에서 사용자가 한다.
- **태블릿 두 칸**: 백업 설정이 오른쪽 칸에 열려도 같은 줄과 같은 동작이다.

## 요구사항

### Functional Requirements

- **FR-001**: 드라이브 연결을 사용자가 시작할 때(백업 화면 연결하기, 다시 연결, 계정 변경) 두 플랫폼 모두 구글 계정 선택 창을 띄운다. 예외는 예전 앱 계정을 먼저 보이는 홈 카드(스펙 003 FR-036)다.
- **FR-002**: 연결을 끊어도 구글 쪽 권한은 거두지 않는다. 드라이브의 백업 파일도 지우지 않는다(스펙 003 FR-004, 헌법 I).
- **FR-003**: 백업 설정의 "계정" 묶음 [구글 계정] 줄(이메일 값)에 화살표를 달고 누를 수 있게 한다. 백업 설정은 연결되어 있거나 다시 연결이 필요한 상태에서만 열린다. 다시 연결이 필요한 상태에서도 연결했던 이메일을 보인다.
- **FR-004**: [구글 계정] 줄은 확인 창 없이 바로 계정 선택 창을 띄운다.
- **FR-005**: 다른 계정을 고르면 처음 연결과 같은 흐름을 탄다: 이 기기의 이전 계정 백업 기록을 지우고, 자동 백업 값은 지키고, 새 계정 드라이브에서 백업을 찾아 있으면 합치기를 권하고 없으면 바로 첫 백업을 한다.
- **FR-006**: 같은 계정을 고르면 이 기기의 백업 기록을 그대로 둔다.
- **FR-007**: 계정 선택을 취소하거나 연결에 실패하면 이전 계정 연결을 그대로 둔다. 취소는 아무 안내도 하지 않고, 실패는 지금의 연결 실패 안내를 쓴다.
- **FR-008**: 백업이 올라가는 중이거나 복원이 도는 중에는 계정을 바꾸지 않는다. [구글 계정] 줄을 누르면 계정 선택 창 대신 까닭을 토스트로 보인다.
- **FR-009**: 한 번의 백업·복원은 한 계정의 드라이브만 쓴다. 계정이 바뀐 뒤 앞 계정에서 받은 토큰이나 이어 올리기 주소를 쓰지 않는다.
- **FR-010**: 바꾼 뒤 복원 목록과 백업 상태는 새 계정 것만 보인다.
- **FR-011**: 계정 이메일과 계정 고유값은 로그, 사용 통계, 오류 보고에 넣지 않는다(헌법 II, 스펙 003 FR-032).
- **FR-012**: 앱 DB 구조, 설정 저장 구조, 드라이브 백업 형식은 바꾸지 않는다.
- **FR-013**: 새 문구는 한국어·영어·일본어로 함께 넣는다.

### Key Entities

- **연결 계정**: 이 기기가 백업에 쓰는 구글 계정 하나(고유값, 화면에 보일 이메일). 바뀌면 그 계정의 백업 기록만 남는다.
- **백업 기록**: 마지막 성공 시각, 마지막 스냅샷, 실패 기록, 드라이브 폴더 위치, 이어 올리기 주소. 계정마다 따로이고 계정이 바뀌면 지운다.

## Success Criteria

### Measurable Outcomes

- **SC-001**: Android와 iOS 모두 연결을 끊었다 다시 이을 때 10번 중 10번 계정 선택 창이 뜬다.
- **SC-002**: 연결된 상태에서 [구글 계정] 줄 → 계정 고르기까지 두 번 누르면 다른 계정으로 바뀐다.
- **SC-003**: 계정을 바꾼 뒤 이전 계정 드라이브의 백업 파일 개수와 내용은 바꾸기 전과 같다(왕복 확인).
- **SC-004**: 바꾼 뒤 첫 백업은 새 계정 드라이브에만 생기고, 이전 계정 드라이브에는 새 파일이 생기지 않는다.
- **SC-005**: 취소, 오프라인 실패, 권한을 뺀 허용 세 경우 모두 이전 계정 연결이 그대로 남는다. iOS 권한을 뺀 허용은 남지 않으면 "다시 연결이 필요해요"로 보인다(Edge Cases).

## Assumptions

- 계정 추가와 비밀번호 입력은 구글 화면에서 사용자가 한다. 앱은 계정 목록을 직접 보이지 않는다.
- 구글 계정 선택 창의 모양과 문구는 운영체제·구글이 정한다. 앱 문구가 아니다.
- 이전 계정의 백업을 지우는 기능은 넣지 않는다. 지우려면 사용자가 드라이브에서 직접 지운다.
- 이전 계정에 마지막 백업을 한 번 더 권하는 안내(Daylio)는 넣지 않는다. 일기는 기기에 있고 새 계정으로 모두 올라가며, 이전 계정의 백업도 그대로 남는다.
- 레거시 `app/`과 예전 앱 백업 형식은 건드리지 않는다.
